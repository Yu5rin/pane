# 設定項目一覧

Paneの設定項目の一次資料。C#側(`Pane/AppSettings.cs`)・ブリッジのJSON・HTML製設定画面
(`src/settings.js`)・実際に効かせる場所(`src/main.js` / `src/editor.js` / C#各サービス)の
4か所で同じキーを使うため、**キー名と取りうる値はこのファイルを正とする**。

Typoraの設定項目は公式のi18nリポジトリ(`typora/Typora-i18n` の `Base.lproj/Panel.strings`)を
一次情報として網羅した。一般的なテキストエディタ(メモ帳・VS Code等)にある項目も併せて拾っている。

## 対象外とした項目

外部へ送るものが増える機能は搭載しない(仕様書 第4.2節)。以下は**意図的に実装しない**。

| Typoraの項目 | 対象外の理由 |
| --- | --- |
| Send Anonymous Usage Info | 外部送信 |
| Image Uploader (PicGo / PicList) | 外部アップロード |
| Get Themes / theme.typora.io | 外部ダウンロード |
| Typora Server | 外部通信 |

更新の確認(Typoraの`Check updates automatically / Updater`にあたるもの)は、当初この一覧でも
対象外としていたが、仕様書 第4.1a節(U-01〜U-07)として実装した。通信するのは「新しい版は
ありますか」という問い合わせだけで、文書や使用状況は送らない。入れ替えは利用者が
「更新する」を押したときにしか始まらず、起動時の確認自体も設定で止められる。
「利用者が知らないうちにPaneが書き換わっていることはない」という一線は保っている。
関係するキーは下の「詳細」と「バージョン情報」を参照。
| ライセンス認証まわり | Paneは認証を持たない |

以下はPaneの設計上そもそも概念が無いため対象外。

| Typoraの項目 | 対象外の理由 |
| --- | --- |
| Window Style (Classic / Seamless / Unibody) | Paneはタイトルバーを持たない単一の外観に統一済み |
| Pandoc Path / LaTeX Engine / PDF Engine 等の詳細 | Pandocは検出のみで、引数の細かい設定は持たない |

| `startupFolderPath` | string? | null | 同上(`customFolder`のとき) |
| `quitOnLastWindowClosed` | bool | true | C# `PaneApplicationContext.OnWindowClosed`(**UIとチェックの意味が逆**。下記注記参照) |
| `preloadOnStartup` | bool | false | C# `StartupService` |
| `pregenerateWindows` | bool | true | C# `PaneApplicationContext.PregenerateSettingsWindow` / `PregenerateHelpWindow` |
| `showStatusBar` | bool | true | JS `main.js` |
| `showOutlineByDefault` | bool | false | JS `sidebar.js` |
| `collapsibleOutline` | bool | true | JS `sidebar.js` |
| `sidebarWidthPx` | int(180〜600) | 240 | JS `sidebar.js` / C# `MainForm`(**隠し設定**。下記注記参照) |
| `recordRecentFiles` | bool | true | C# `MainForm`(最近使ったファイルの記録) |
| `zoomWithCtrlWheel` | bool | true | JS `main.js` |
| `tooltipDetail` | `"none"` \| `"minimal"` \| `"standard"` \| `"detailed"` | `standard` | JS `main.js` / `settings.js`(下記注記参照) |
| `displayMode` | `"window"` \| `"tab"` | `window` | JS `main.js` / C# `PaneApplicationContext`・`MainForm`(**隠し設定**。下記注記参照) |

> **`displayMode` は隠し設定。** タブ形式(仕様書 第2.10節 C-14、第3章「表示形式」)自体は
> 実装済みで動作するが、ユーザー指示により**設定画面(`src/settings.js`)には切替UIを一切置かない**
> (「ウィンドウ形式から変更できないようにする」ため)。有効にするには `settings.json` を
> 直接テキストエディタで開き `"displayMode": "tab"` と書き換える必要がある(次回起動、または
> 設定の再読込で反映)。設定ファイルの場所は「バージョン情報」カテゴリで確認できる。
> 既定(`window`)の挙動は本機能追加によって一切変わらない。

> **`sidebarWidthPx` も隠し設定。** サイドバーの右端をドラッグして幅を変える(180〜600px、
> かつウィンドウ幅の50%を超えない)機能自体は常に有効。ドラッグ・ハンドルのダブルクリック
> (既定240pxへ戻す)のたびに`set-sidebar-width`メッセージでC#側へ永続化される。
> ドラッグで直接変えられる値のため、設定画面には切替UIを置かない(二重になるため)。

> **`quitOnLastWindowClosed` はUIとキー名の意味が逆。** ユーザーが「チェックを付ける=常駐する」
> だと誤解した実機報告を受け、設定画面(`src/settings.js`)のチェックボックスは
> **「最後のウィンドウを閉じても常駐させる(次回の起動が速くなります)」** という、
> チェックON=常駐する向きの文言・挙動にした。一方でキー名・既定値(`true`)・保存されるJSONの
> 値・C#側の判定ロジック(`PaneApplicationContext.OnWindowClosed`、約371行目)は
> **一切変更していない**(意味は従来どおり「trueなら最後のウィンドウを閉じたときに終了する」)。
> そのため、
> - チェックON(常駐させる) → `settings.json` に保存される値は `"quitOnLastWindowClosed": false`
> - チェックOFF(常駐させない=閉じたら終了) → 保存される値は `"quitOnLastWindowClosed": true`
>
> という、**UIのチェック状態とJSON上の値が常に逆になる**。`fieldCheckbox()` の
> `{ invert: true }` オプション(`wireCommonFields`内の`data-invert`処理)がこの反転を担う。
> 既存の設定ファイル・C#側は変更していないため、古い設定ファイルや手編集した
> `settings.json` ともそのまま互換性がある(意味が変わるのは設定画面の見た目だけ)。
>
> すぐ下の `preloadOnStartup`(PCの起動時からあらかじめ常駐しておく)とは独立した設定。
> 前者は「PC起動時から常駐するか」、こちら(`quitOnLastWindowClosed`)は
> 「ウィンドウを閉じたときに常駐し続けるか」という別軸の設定で、紛らわしいため設定画面の
> 説明文(`settings-field-desc`)でも互いの違いに触れている。

> **`tooltipDetail`(マウスカーソルを合わせた時に出る説明の詳しさ)。**
> `none`(表示しない)/ `minimal`(最低限。現在の状態を示す情報のみで機能説明は付けない)/
> `standard`(既定。ネットリテラシーのある人が見て分かる程度)/ `detailed`(詳しい。
> 「何ができてどうなるか」を具体的に説明)の4段階。GraftのUIに倣い、
> `none`/`standard`/`detailed`の3段階に加えて`minimal`を追加している。
>
> 文言そのものは1箇所(`src/tooltips.js`のTOOLTIPS)に集約している。理由は
> (1) 4段階×全要素ぶんの文言をHTML/各JSに直書きすると保守できないこと、
> (2) 将来の多言語対応(実装予定)で文言が散らばっていると詰むこと、
> (3) 将来のF1ヘルプ(説明書、今回は未実装)からも同じテーブルを再利用する想定であること
> (`TOOLTIPS`の`category`・`standard`・`detailed`がそのまま説明書の下書きとして使える形にしてある)。
>
> 識別子は対象要素の`id`属性を使い、`id`を持たない要素(サイドバーのタブボタン等)には
> `data-tip="任意の識別子"`を付ける方式にした(既存HTMLへの変更を最小にするため)。
> 設定画面自身の各項目(チェックボックス・セレクト等)は、この一覧表のキー名をそのまま
> 識別子として使う(`src/settings.js`の`field*`ヘルパーが自動で`data-tip="キー名"`を付ける)。
>
> `minimal`は「今どうなっているか」を示す情報が中心で、機能の説明は付けない、と解釈した。
> ステータスバーの文字コード等は現在の値のみ(例: `UTF-8`)、アイコンだけで用途が分からない
> ボタン(設定・ヘルプ等)は名前のみ、設定画面の各項目はラベル自体で用途が分かるため出さない
> (`minimal`・`none`のいずれでも設定画面はツールチップを一律に抑制する)。
>
> ショートカットキー(例: `(Ctrl+,)`)は、`none`を除く全段階で常に付記する。
>
> 文言テーブルに個別のエントリが無い要素は、`none`以外では元々の`title`属性(または
> 設定画面の場合はラベル・説明文から自動生成した文言)をそのまま使うフォールバックにしている
> (`src/tooltips.js`の`resolveTooltip`/`applyTooltip`、`src/settings.js`の
> `FIELD_TOOLTIP_FALLBACK`/`applySettingsTooltips`参照)。

`spellCheckAutoCorrect`(スペルチェックの自動修正)はWebView2の制約により**実装不能**。
`spellCheckEnabled`はCodeMirrorの`.cm-content`へ`spellcheck`属性を立てるだけで、下線表示や
候補一覧はWebView2(Chromiumエンジン)が持つOS標準のスペルチェック機能をそのまま使っている。
その自動修正(オートコレクト)はブラウザ・WebView2側にAPIが無く、JSからON/OFFを制御する手段が
存在しない(Windowsのテキスト入力設定に従う)。設定項目自体は残し(値の保存・送受信は行う)、
設定画面にはその旨を明記する。

`codeIndentSize`について補足(ユーザー報告「コードモードのインデントが小さすぎる。設定を
変えても変わらない」への対応で判明した点): CodeMirrorの`indentUnit`は「Tabキーで新しく
挿入するインデントの幅」を決めるだけで、**その文書に既に書かれているインデントの表示幅には
一切影響しない**。タブ文字でインデントされたファイルは別途`EditorState.tabSize`が表示幅を
決めており、以前はこれがどこにも設定されておらずCodeMirror既定の4に固定されていた
(=`codeIndentSize`を2/4/8に変えてもタブ文字の見た目が変わらなかった)。今回`codeIndentSize`を
`tabSize`にも連動させ、タブ文字インデントについては設定どおりに表示幅が変わるようにした。
一方、**スペースで書かれているインデントの見た目の幅はCSSでは伸縮できない**(スペースは
ただの文字であり、フォントの文字幅ぶんの幅を持つため)。これを変えるには文書自体を
書き換える(再インデントする)しかなく、今回はその機能まで踏み込むと既存コードの意味的な
崩壊(Pythonの意味を持つ空白など)のリスクがあるため見送った。代わりに、コードモードへ
インデントガイド(縦線、`codeIndentSize`と同じ間隔)を追加し、スペースインデントであっても
深さが一目でわかるようにした。

`codeIndentGuides`について補足(ユーザー意見「マーカーをつなぐために使用しているだけで、
インデントごとに罫線する必要はないと考えている」への対応): 当初はインデントガイドの
ON/OFFを持たず常にコードモードで有効(`all`相当)にしていたが、上記の意見を受けて3択の設定に
した。既定は`fold`(折りたたみできる範囲のみ)で、関数・オブジェクト・配列など折りたたみ
マーカーが実際に存在する階層にだけ、その範囲の開始行から最終行まで縦線を引く(折りたたみに
関係ない浅い/深いインデント段には線を引かない)。全深さに一律で線を引く旧来の挙動を残したい
場合は`all`を選ぶ。`none`にすると縦線を一切出さない。

**マーカーの位置を本文エリアの左端に固定する変更(直近の修正)に伴い、`fold`モードの説明を
「マーカーの中心から」から「その範囲の開始行から」へ改めた。** 以前はマーカーの横位置が
インデントの深さに応じて動く設計だったため、縦線をマーカーの中心に合わせて引いていたが、
その可変位置が複数の不具合(タブ幅での位置ずれ・インデント幅変更時の未更新・インデント
ガイドとの二重線)の原因になっていたため、VS Codeと同じくマーカーの位置を「本文エリアの
左端から常に一定の隙間」に固定する方針に変更した。マーカーが固定位置になったことで、縦線は
マーカーの位置とは完全に切り離され、実際のコードのインデント位置(行頭空白の終端)を
そのまま表現するようになった。あわせて、"all"・"fold"どちらのモードもCSSの反復
グラデーションではなく実DOM要素の1つの仕組みで描くよう統合し(以前は"all"だけ別方式で、
位置の決め方が食い違って線がずれることがあった)、折りたたみ範囲の最終行では縦線を
行の縦中央で止めてL字(└)の横棒を出す終端表現を一時追加した。

**その後、Windows実機でのユーザーフィードバックを受けてL字は廃止した。** 現在は縦線を引く
行の範囲をVS Codeに合わせている(開始行自身には引かず、開始行の次の行から、その範囲の階層
より深い行にだけ引く。閉じ括弧・閉じタグだけの行にも引かない)ため、L字という終端表現自体が
不要になった。縦線はどの行でも行の全高をまっすぐ塗るだけで、横棒による終端表現は無い。

マーカーへのマウスホバー時、対応する折りたたみ範囲の縦線だけを`--fold-guide-hover`
(既定`var(--accent)`)で強調する機能も追加した。マーカーが固定位置になったことで「どの範囲が
畳めるか」が見た目で分かりにくくなった埋め合わせで、ホバーの間だけ始点から終点までを
ひと目で示す。

`Pane/AppSettings.cs` の `EditorPaddingX`/`GetEffectiveEditorPaddingLeft`/
`GetEffectiveEditorPaddingRight` が、`editorPaddingLeft`/`editorPaddingRight` の

設定済みの場合に限り、その値を左右どちらにも引き継ぐ移行を行う(一度でも新しい設定
画面で保存すると、以後はこの移行を行わなくなる)。

## 詳細 (advanced)

| キー | 型・値 | 既定 |
| --- | --- | --- |
| `enableDebug` | bool | false |
| `verboseLogging` | bool | false |
| `showHiddenFilesInTree` | bool | false |
| `fileTreePatterns` | string[](glob。`!`始まりで除外) | `[]` |

`verboseLogging`は「詳細ログを記録する」。普段は起動・保存・エラーといった節目だけを記録し、
これを有効にするとメニュー操作や画面の更新まで残す(`Pane/Logger.cs`の`LogLevel.Debug`)。
保存した瞬間から効き、再起動は要らない。書き込みは裏でまとめて行うため、有効にしても
動作は遅くならない。環境変数`PANE_LOG_LEVEL`を指定した場合はそちらが優先される。

`addToPath`はexeのあるフォルダをユーザー環境変数PATH(`HKCU\Environment`)へ追加するか
(仕様書 F-14「コマンドラインから開く」)。管理者権限は不要。ON/OFFの切り替えはC#
`Pane/PathEnvironmentService.cs`が担い、変更のたびに`WM_SETTINGCHANGE`をブロードキャストして
実行中の他プロセスにも反映させる。既に登録済みなら重複登録しない。

- 設定ファイルの場所を開く
- 設定をすべて既定に戻す
- 最近使ったファイルの履歴を消去
- ファイル単位の編集モード記憶を消去
- Windowsの「既定のアプリ」設定を開く

## バージョン情報 (versionInfo)

設定値(保存対象)は無く、すべて表示専用の環境情報とボタン。`settings` 応答にのみ含まれ、
`save-settings` では送らない(`draft`には保持するが `buildSavePayload` の対象外)。

| キー | 型・値 | 内容 |
| --- | --- | --- |
| `appVersion` | string | アセンブリのバージョン(取得不可なら「不明」) |
| `webView2Version` | string | WebView2ランタイムのバージョン(未導入等で取得不可なら「不明」) |
| `dotNetVersion` | string | `Environment.Version` |
| `logFolderPath` | string | ログファイルの置き場(`Pane/Logger.cs` の `FilePath` の親フォルダ) |
| `themeFolderPath` | string | カスタムCSSの既定フォルダ(`Pane/ThemeFolderService.cs`) |
| `licenses` | `{ name, license }[]` | Pane本体 + 主要な同梱OSSのライセンス一覧 |
| `settingsFilePath` | string | (既存)設定ファイルの場所。この画面にも表示する |
| `updateCheckUrl` | string | 更新の問い合わせ先(仕様書 U-02)。画面に表示するだけで、ここからは編集できない |

このカテゴリで唯一の保存対象が次の1つ。更新の話がまとまっている場所に置きたいため、
「詳細」ではなくここに出している。

| キー | 型・値 | 既定 |
| --- | --- | --- |
| `checkUpdateOnStartup` | bool | true |

`checkUpdateOnStartup`は「起動時に新しい版があるか確認する」(仕様書 U-06)。オンなら起動の
たびに配布元へ問い合わせ、新しい版があれば画面上部の帯で知らせる。知らせるだけで、
入れ替えは利用者が「更新する」を押したときにしか始まらない。オフにすると、起動時の通信は
一切行わなくなる。

問い合わせ先の`updateCheckUrl`(既定は`https://api.github.com/repos/Yu5rin/pane/releases/latest`)は
設定画面から編集できないが、この画面に表示され、設定ファイルを直接書き換えれば変えられる。
コードに直書きしていないのは、どこへ通信するのかを利用者が確かめられるようにするため。
空にすれば更新の確認そのものを止められる。https以外のURLは拒否する。

ボタンとして置くもの(設定値ではない。押すとC#側へメッセージを送るだけで応答は待たない):

- 設定ファイルの場所を開く(`open-settings-file`。既存)
- ログフォルダを開く(`open-log-folder`)
- 今日のログを開く(`open-today-log`)
- カスタムCSSフォルダを開く(`open-theme-folder`。「外観」カテゴリの
  「サンプルのあるフォルダを開く」ボタンと同じメッセージ)

## 設定ファイルにあるが、画面に出さないもの

設定ファイル(`settings.json`)には、利用者が選ぶ項目のほかに、Pane自身の覚え書きも入る。
画面には出さず、設定画面との送受信にも含めない。ここに挙げるのは、設定ファイルを直接
開いた人が「これは何だろう」と迷わないため。

| キー | 型 | 何のためのものか |
| --- | --- | --- |
| `recentFiles` | string[] | 最近使ったファイル(仕様書 F-09)。先頭が最新 |
| `lastFolderPath` | string | 最後にサイドバーで開いていたフォルダ(第2.8節) |
| `openFilePaths` | string[] | 前回終了時に開いていたファイル(セッション復元用) |
| `windowX` / `windowY` / `windowWidth` / `windowHeight` | number | ウィンドウの位置と大きさ(Normal時のみ記録) |
| `windowMaximized` | boolean | 直前に閉じたウィンドウが最大化されていたか。セッション最初の1枚だけ復元に使う |
| `pendingUpdateNoticeTag` | string | 見つけたのにまだ画面に出せていない新しい版のタグ(U-06)。出せたら消える |
| `pendingUpdateNoticeMessage` | string | 上と一緒に見せる案内の文面 |
| `updateFeedETag` | string | 配布元のフィードを前回受け取ったときの目印。次回はこれを添えて尋ね、変わっていなければ本文を受け取らずに済ませる |
| `updateFeedLatestTag` | string | 上の目印を受け取ったときに読み取った最新のタグ。「変わっていない」と返ってきたらこれを使う |

いずれも消して構わない(次に使うときに作り直される)。

## 送受信の約束

- `apply-settings`(全ウィンドウへ配信): 上記のうち**JS側で効かせる項目のみ**を含める。
  一覧系(`installedFonts` 等)は含めない。
- `settings`(設定画面を開いたときの応答): 上記**すべて**に加えて、
  `installedFonts`(string[])・`monospaceFonts`(string[])・`pandocAvailable`(bool)・
  `settingsFilePath`(string)・上記「バージョン情報」の各キーを含める。
- `save-settings`(設定画面からの保存): 上記すべてを `settings` オブジェクトとして送る。
  C#側は知らないキーを無視し、値の妥当性(列挙値・数値範囲)を検証して不正なら既定値に倒す。
  「バージョン情報」カテゴリの各キーは表示専用のため送らない。
