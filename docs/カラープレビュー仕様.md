# コードモードのカラープレビュー仕様

コード中の色リテラル(`#ff6600`、`rgb(255,102,0)` 等)を、その色で見せる機能の仕様。

## 1. 目的と適用範囲

- **適用先**: コードモード全体、および Markdownモード内のコードフェンス(``` ```` ```)の中。
  Markdownの本文やプレーンテキストモードには適用しない
  (通常の文章に出てくる `#123456` のような文字列を誤って色として扱わないため)。
- **設定**: `colorPreviewInCode`(既定 `true`)で無効化できる。
  設定画面の「編集」カテゴリに置く(`docs/設定項目一覧.md` に追記すること)。

## 2. 認識する記法

| 記法 | 例 | 備考 |
| --- | --- | --- |
| 16進 | `#f60` `#f60c` `#ff6600` `#ff6600cc` | 3/4/6/8桁。直前が英数字・`_`の場合は無視 |
| rgb / rgba | `rgb(255, 102, 0)` `rgba(255,102,0,.8)` `rgb(255 102 0 / 80%)` | 旧カンマ記法・新スペース記法の両方 |
| hsl / hsla | `hsl(24, 100%, 50%)` `hsl(24 100% 50% / .8)` | 同上 |
| CSS色名 | `red` `rebeccapurple` | **CSS系の言語(css/scss/less/sass/stylus)のときだけ**。
それ以外の言語では変数名・識別子と紛れるため無効 |

`0xFF6600` のような表記は、色なのか単なる数値なのか判別できないため対象外とする。

## 3. 表示

1. リテラルの**直前に小さな色見本(スウォッチ)**を差し込む。
2. リテラルの**文字色**をその色にする。

### 3.1 スウォッチ

- 大きさ 0.85em の角丸(2px)の正方形。文字の直前に 0.25em の余白を空けて置く。
- **枠線** `1px solid` を必ず引く。色は現在のテーマの文字色を35%不透明にしたもの。
  これが「白い背景に白の色見本が消える」ことへの対策になる。
- 半透明の色(`rgba(...,.3)` 等)は、市松模様(CSSのlinear-gradientで作る)の上に
  その色を重ねて表示する。透明度が一目で分かるようにするため。
- クリックできる要素にはしない(誤操作を避ける。色の変更は第4章の右クリック経由で行う)。

### 3.2 文字色 ― 背景に紛れないための処理

**そのまま文字色にしてはいけない。** 背景色に近い色(ライトテーマでの白系、
ダークテーマでの黒系)を指定すると文字が読めなくなるため、次の手順で補正する。

1. アルファを持つ色は、まず現在の背景色(`--paper` の実効値)の上に合成して不透明色にする。
2. 背景色との **WCAGコントラスト比** を計算する。
   相対輝度 `L = 0.2126R + 0.7152G + 0.0722B`(各成分はsRGBの逆ガンマ補正後)、
   コントラスト比 `(L明 + 0.05) / (L暗 + 0.05)`。
3. 比が **3.0 以上**ならそのまま文字色に使う。
4. 3.0 未満なら、現在の文字色(`--ink`)へ向けて 5% 刻みで混ぜ、
   初めて 3.0 以上になった色を文字色にする。
   これにより**色味は保ったまま可読性を確保**する
   (真っ白 `#ffffff` はライトテーマではごく薄いグレーではなく、
   `--ink` 寄りの読める明度まで暗くなる)。
5. 補正が入った場合でも**スウォッチは必ず元の色そのまま**で表示する。
   正確な色はスウォッチが担保し、文字は読みやすさを優先する、という役割分担にする。

計算結果は色文字列をキーにしたキャッシュに入れる(同じ色が何度も出てくるため)。
テーマ切り替え・カスタムCSS適用時はキャッシュを破棄して再計算する。

## 4. カラーピッカー(右クリック →「色を変更…」)

色リテラルを右クリックすると、コンテキストメニューの先頭に **「色を変更…」** が出る
(`docs/コンテキストメニュー仕様.md` の文脈判定に1つ追加する。ラベルの左には
その色のスウォッチを付ける)。選ぶとカラーピッカーのパネルが開く。

### 4.1 パネルの構成

上から順に。

1. **プレビュー行** ― 現在の色の大きめのスウォッチと、`#14599F` のような16進表記、
   `HSL(210°, 78%, 35%)` のような補助表記。
2. **色相・彩度・明度の選択** ―
   - 彩度×明度の四角形(ドラッグで選択、選択位置に白丸のハンドル)
   - その下に色相スライダー(虹色のグラデーション)
   - 元のリテラルがアルファを持っていた場合のみ、不透明度スライダー(市松模様の上に表示)
3. **数値入力** ― R / G / B の3つの数値入力と、16進表記の入力欄。
   どれを直接編集しても他が追従する。
4. **スポイト** ― `EyeDropper` API が使える場合のみボタンを出す
   (画面上の任意の色を吸い取る。使えない環境ではボタン自体を出さない)。
5. **配色パレット** ― 下記5種類を、それぞれ **5色ずつ** 横並びで表示する。
   各見出しは「単色」「類似色」「補色」「三角配色」「四角配色」。

### 4.2 配色パレットの生成規則

基準色のHSLを `(h, s, l)` とする。角度は360で剰余を取る。

| 種別 | 5色 |
| --- | --- |
| 単色 | 色相・彩度はそのまま、明度を `l` を中心に 5段階(おおよそ `l-30% / l-15% / l / l+15% / l+30%`、0〜100%でクランプ) |
| 類似色 | `h-30 / h-15 / h / h+15 / h+30`(彩度・明度はそのまま) |
| 補色 | 基準色の明るい版・基準色・基準色の暗い版・補色(`h+180`)・補色の暗い版 |
| 三角配色 | `h` / `h+120` / `h+240` / `h` の明るい版 / `h+120` の明るい版 |
| 四角配色 | `h` / `h+90` / `h+180` / `h+270` / `h` の明るい版 |

各色にはマウスを乗せると16進表記のツールチップを出す。

### 4.3 挙動

- **リアルタイム反映**: 四角形やスライダーを操作している最中、パネルを閉じずに
  本文の色リテラルを即座に書き換える。書き換え中の中間状態は
  **アンドゥ履歴に積まない**(`Transaction.addToHistory.of(false)`)。
  パネルを閉じた時点で、開いた時の色 → 最終的な色 という**1回分の変更としてまとめて**
  アンドゥできるようにする。
- **パレットの色をクリック**した場合はその色を確定し、**パネルを閉じる**。
- `Esc` またはパネルの外をクリックすると、**開いた時の色に戻して**閉じる(キャンセル)。
  「OK」相当の確定は、パレットのクリックか、パネル内の「適用」ボタンで行う。
- **表記は元のリテラルに合わせる**。`#ff6600` を編集したら `#ff6600` 形式のまま、
  `rgb(255,102,0)` を編集したら `rgb(...)` 形式のまま書き戻す。
  16進の桁数(3桁/6桁)とアルファの有無も維持する
  (3桁で表現できない色になった場合のみ6桁へ広げる)。

### 4.4 表示位置 ― 変更箇所を隠さないこと

- 対象のリテラルの**矩形(`view.coordsAtPos`)を求め、その下に出す**。
  下に入りきらない場合は上に出す。上下どちらにも入らない場合は、
  リテラルの**左右どちらか空いている側**へずらす。
- どの場合も、パネルの矩形がリテラルの矩形と**重ならない**ことを保証する。
- 画面(WebView2のビューポート)からはみ出さないようクランプする。
- パネルは編集領域の上に重ねる(`position: fixed`)。
  対象のリテラルには、開いている間だけ枠線のハイライトを付けて、どこを編集中か分かるようにする。

## 5. 実装方針

- `src/editor.js` に `ViewPlugin` として実装し、**表示範囲(`view.visibleRanges`)だけ**を
  走査する。ファイル全体を毎回正規表現で舐めない(性能要件。既存のインライン装飾と同じ作法)。
- スウォッチは `WidgetType`、文字色は `Decoration.mark` で当てる。
- 文字色は `Decoration.mark({ attributes: { style: "color:..." } })` で直接指定する
  (色ごとにCSSクラスを作ることはできないため)。
- コードフェンス内かどうかの判定は、既存の構文木ベースのコードフェンス判定を再利用する。
- カーソルがリテラル上にあるときもスウォッチは出したままにする
  (ライブプレビューの他の装飾と違い、編集の邪魔にならない大きさのため)。

## 6. 検証(`.verify-colorpreview.mjs`)

- コードモードで各記法(3/4/6/8桁16進、rgb/rgba の両記法、hsl/hsla、CSS色名)が
  認識され、スウォッチと文字色が付くこと。
- CSS色名がCSS系以外の言語では色として扱われないこと。
- Markdownのコードフェンス内では効き、本文では効かないこと。
- `#ffffff` がライトテーマで背景に埋もれない文字色(コントラスト比3.0以上)になること。
  `#000000` がダークテーマで同様であること。
- 半透明の色で市松模様の背景が出ること。
- `colorPreviewInCode: false` で一切表示されないこと。
- 直前が英数字の場合(`abc#ff0000`)に反応しないこと。
- 1万行のファイルで、表示範囲外の色リテラルが装飾対象になっていないこと(性能)。

カラーピッカー(第4章):

- 色リテラルの右クリックメニューの先頭に「色を変更…」が出ること。
  色以外の場所では出ないこと。
- 選ぶとパネルが開き、**対象のリテラルの矩形と重ならない**位置に出ること
  (下・上・左右のどれに逃げた場合も重なりが0であること)。
  ビューポートからはみ出さないこと。
- 色相スライダーを動かすと、パネルを閉じないまま本文の文字列が書き換わること。
- 中間状態がアンドゥ履歴に積まれず、閉じた後の1回のアンドゥで元の色に戻ること。
- 5種類のパレットがそれぞれ5色ずつ出ること。生成規則どおりの色相になっていること。
- パレットの色をクリックすると、その色に確定してパネルが閉じること。
- `Esc` で開いた時の色に戻って閉じること。
- 元が `rgb(...)` なら `rgb(...)` のまま、`#f60` なら3桁のまま書き戻されること。
  アルファ付きのリテラルではアルファが維持されること。
- ページエラー・コンソールエラーが0件であること。
