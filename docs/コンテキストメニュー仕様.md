# 右クリック(コンテキスト)メニュー仕様

Paneの右クリックメニューの仕様書。Typoraの右クリックメニューを参考にしつつ、
Paneの構成(WinForms + WebView2 + CodeMirror 6)に合わせて設計する。

## 0. 大原則

1. **ブラウザ(WebView2)の既定コンテキストメニューは一切表示しない。**
   `CoreWebView2Settings.AreDefaultContextMenusEnabled = false` を本体ウィンドウ
   (`Pane/MainForm.cs`)・設定ウィンドウ(`Pane/SettingsWindow.cs`)の両方で設定する。
   保険としてJS側でも `document.addEventListener("contextmenu", e => e.preventDefault(), true)`
   を最外周に置き、独自メニューを出さない場所でも既定メニューが出ないようにする。
2. **表示はネイティブポップアップ**(`Pane/NativeMenu.cs` の `ToolStripDropDownMenu`)を使う。
   メニューバーのドロップダウンと同じ理由(ウィンドウ外へはみ出して表示できる)・同じ見た目。
   ブリッジが無い環境(ブラウザでの単体確認)ではHTMLの `.menu-dropdown` にフォールバックする。
3. **コマンドの実装はJS側に置く。** C#は表示と「選ばれたid」の返却だけを行う。
   既存の `open-menu` / `menu-command` / `menu-closed` と同じ流儀。
4. **文脈に無いものは出さない。** 表の上でだけ表の操作、リンクの上でだけリンクの操作。
   常に同じ長大なメニューを出さない(Typoraと同じ考え方)。
5. **右クリック位置にカーソルを移す。** クリック位置が現在の選択範囲の外なら、
   まずその位置へキャレットを移してからメニューを出す(一般的なエディタの挙動)。
   選択範囲の中を右クリックした場合は選択を保持する。

## 1. C#側との通信

### 1.1 JS → C#

```jsonc
{
  "type": "open-context-menu",
  "x": 320,          // WebView2内のCSSピクセル座標(クリック位置)
  "y": 180,
  "items": [ /* open-menu と同じ MenuItemData 形式 */ ]
}
```

`items` の各要素は既存の `open-menu` とまったく同じ形
(`id` / `label` / `shortcut` / `enabled` / `checked` / `separatorAfter` / `note` / `submenu`)。
そのため C#側は `Pane/NativeMenu.MenuItemData` と `ParseMenuItems()` をそのまま再利用する。

### 1.2 C# → JS

既存の `menu-command` / `menu-closed` をそのまま使う。
`menu-closed` の `menu` には `"__context__"` を入れる
(メニューバーの `File` 等と衝突しない固定値。`src/commands.js` の
`nativeOpenMenuName` との突き合わせにそのまま乗る)。

### 1.3 表示位置

`open-menu` と違い、`ToolStripDropDownDirection.BelowRight` ではなくクリック位置そのものに出す。
座標変換(`DeviceDpi / 96.0` → `_webView.PointToScreen`)は `HandleOpenMenuRequest` と同じ。

## 2. 本文(CodeMirror)上のメニュー

右クリック位置の構文要素を `syntaxTree` から判定し、**該当するセクションだけ**を積み上げる。
順序は上から「文脈固有 → 編集(切り取り/コピー/貼り付け) → 書式 → 段落 → その他」。

### 2.1 常に出る「編集」セクション

| 項目 | 有効条件 | 実装 |
| --- | --- | --- |
| 切り取り | 選択あり | `document.execCommand("cut")` |
| コピー | 選択あり | `document.execCommand("copy")` |
| 貼り付け | 常時 | 既存の貼り付け経路(`navigator.clipboard.readText()` + CodeMirrorへ挿入) |
| プレーンテキストとして貼り付け | 常時 | 既存 `edit.pastePlain` |
| すべて選択 | 常時 | CodeMirror `selectAll` |

Markdownモードでは続けて以下も出す。

| 項目 | 有効条件 |
| --- | --- |
| マークダウンとしてコピー | 選択あり(既存 `edit.copyMarkdown`) |
| HTMLとしてコピー | 選択あり(既存 `edit.copyHtml`) |

### 2.2 選択がある場合の「書式」サブメニュー

`書式` サブメニューとして畳む(平坦に並べるとメニューが長くなりすぎるため)。
太字 / 斜体 / 下線 / インラインコード / 打消し線 / ハイライト / 上付き文字 / 下付き文字 /
(区切り) / ハイパーリンク / 書式を消去。
既存の `format.*` コマンドをそのまま使う。

### 2.3 リンクの上

- リンクを開く(既存の外部リンク確認ダイアログを必ず通す)
- リンクのURLをコピー
- リンクを編集…(URL部分を選択してキャレットを置く)
- リンクを解除(`[text](url)` → `text`)

### 2.4 画像の上

- 画像を開く(既定のビューアで開く。C#へ `open-path`)
- 画像のパスをコピー
- 画像のパスを編集…
- 画像を削除(`![alt](path)` を丸ごと削除)
- (オンライン画像の場合)このURLをコピー

### 2.5 表の中

Typoraの表メニュー相当。**これらのアクションは新規実装が必要**(現状は `deleteTableRow` のみ)。

- 行を上に挿入 / 行を下に挿入
- 列を左に挿入 / 列を右に挿入
- (区切り)
- 行を削除 / 列を削除 / 表を削除
- (区切り)
- 列の配置 ▸ 左揃え / 中央揃え / 右揃え / 指定なし
  (区切り行の `:---` / `:---:` / `---:` / `---` を書き換える)

### 2.6 コードブロックの中

- 言語を選択…(既存のコードモード言語選択と同じ一覧を再利用)
- コードブロックの内容をコピー
- コードブロックを削除

### 2.7 見出しの行

- 見出しレベル ▸ 見出し1〜6 / 段落(見出し解除)
  (現在のレベルに `checked` を付ける)

### 2.8 リスト行

既存の `para.listBullet` / `para.listOrdered` / `para.listCheck`(現在の種別に `checked`)。
加えて「インデント」「アウトデント」。

### 2.9 数式ブロック / インライン数式の上

- 数式を編集(ソースを表示)
- 数式を削除

### 2.10 どの文脈でも最後に出る「その他」

- (区切り)
- 元に戻す / やり直す
- (区切り)
- 検索…(`edit.find`)
- 選択箇所を検索(選択ありのとき。選択文字列を検索窓に入れて開く)

### 2.11 選択も文脈も無い(素の段落)場合

編集セクション + 「段落」サブメニュー(見出し1〜6 / 段落 / 引用 / 箇条書き /
番号付きリスト / タスクリスト / 表を挿入 / コードブロックを挿入 / 数式ブロックを挿入 /
水平線)+ その他セクション。

## 3. コードモード / プレーンテキストモード

Markdown固有の項目(書式・段落・表など)は出さない。

- 切り取り / コピー / 貼り付け / すべて選択
- (区切り)
- 元に戻す / やり直す
- (区切り)
- 検索… / 置換…
- (コードモードのみ)言語を選択…

## 4. サイドバー

### 4.1 アウトラインパネルの見出し行

- ここへジャンプ
- 見出しをコピー
- (区切り)
- すべて展開 / すべて折りたたむ

### 4.2 記事リスト・ファイルツリーのファイル行

### 4.3 ファイルツリーのフォルダ行

- フルパスをコピー
- ここに新しいファイルを作成…

## 5. 入力欄(検索窓・設定画面のテキスト入力)

`input` / `textarea` の上では、OS標準に合わせた最小構成にする。

- 元に戻す / やり直す
- (区切り)
- 切り取り / コピー / 貼り付け / 削除
- (区切り)
- すべて選択

設定ウィンドウ(`settings-window.html`)でも同じものを出す。
設定ウィンドウ側は独自のブリッジ(`SettingsWindow.cs`)を持つため、
`open-context-menu` の受け口をそちらにも実装する。

## 6. その他の領域

メニューバー・ステータスバー・サイドバーの余白など、上記に当てはまらない場所では
**何も表示しない**(既定メニューも出ない)。

## 7. 検証

`.verify-contextmenu.mjs` を新規に作り、少なくとも次を確認する。

- ブリッジがあるとき、本文の右クリックで `open-context-menu` が送られ、
  HTMLの `.menu-dropdown` は作られないこと。
- 文脈ごとに期待する項目が入っていること(リンク / 画像 / 表 / コードブロック /
  見出し / リスト / 素の段落 / 選択あり)。
- `input` の上では入力欄用の最小構成になること。
- ブリッジが無いときはHTMLのドロップダウンにフォールバックすること。
- `menu-command` で各アクションが実際に文書へ反映されること
  (表の行挿入・列挿入・削除・配置、リンク解除、画像削除など)。
- ページエラー・コンソールエラーが0件であること。
