# 調査記録

アプリ全体をユーザー視点で点検した結果と、そこから直したものの記録です。

「何を直したか」はコミットログとPRに残りますが、ここに残すのは
**なぜそう直したか、何を調べて何が違ったか、何を直さなかったか**です。
同じ誤りに戻らないための記録なので、役目を終えても消しません。

ソースコード内のコメントからも、根拠としてこれらのファイルを参照しています。
名前を変えるときは参照側も直してください。

## 繰り返し出てきた誤り

同じ形の間違いを繰り返している。次に配色・実測・更新まわりを扱うときは先にここを読むこと。

1. **ある用途向けに調整された色を、別の用途へ流用する。**
   `--ink-sub`（本文上の補助文字用）を記号の地色に、`--accent`（面用）を文字色に、
   `--ink-mute`（本文上）を `--chrome-bg` の上に。いずれもテーマによって
   コントラストが保証されなくなった。

2. **文字サイズごとの基準を取り違える。**
   WCAG の「大きな文字」の緩い基準（3:1）は、太字18.66px以上に限られる。
   11〜12px の文字には 4.5:1 が要る。

3. **手元で測った過去の数字を、実機の現在の数字として扱う。**
   「起動の8割はバンドル評価で約2.2秒」と長く説明していたが、実機ログでは73〜122msだった。
   実機の数字を持たないまま性能の話をしない。

4. **新しい安全策を、それ以前の版から上がってくる環境で考えない。**
   更新の完了マーカーはv1.1.4で入れたので、それ以前に更新した環境には
   「退避ファイルはあるがマーカーは無い」が最初から存在する。一律に異常扱いすると
   正常な環境で警告が出続ける。

5. **直したものが、直したい相手に当たっているかを確かめない。**
   フォルダ走査の使い回しに「打ち切った結果は除く」条件を付けたが、直そうとしていた
   1万件のフォルダがまさに打ち切られる側で、実機では1度も効いていなかった。

6. **計測の道具が結果を変えていないか確かめない。**
   `.cm-content` の `innerText` で行数を数えて22行という誤った数字を出した（正しくは15行）。
   CodeMirrorの各行はブロック要素なので、`innerText` はCSSに従って改行を足す。
   本文は `request-text` で取る。

7. **計測そのものにかかる時間を、計測値に混ぜる。**
   メモリを数え終えてから経過時間を読んでいたため、ウィンドウ表示が56〜82ms
   長く出ていた。枚数とともに報告値だけが伸びるのが兆候だったが、受け流していた。

8. **入口が複数あるものを、入口ごとに塞ごうとする。（2回やった）**
   1回目は事前生成を止める判定を呼び出し元の片方にだけ置き、もう片方（タイマー経由の
   保険）が素通りしていた。2回目は貼り付けの判定を `onPaste` にだけ置き、右クリック
   メニューからの経路（`navigator.clipboard.read` を使う別関数）が素通りしていた。
   **1回目の直後に2回目をやっている。** 実行する側に1つ置けば漏れない。
   あわせて、テストが片方の入口しか見ていないと漏れに気づけない。

9. **調べるための仕掛けを、それが届いた先で使えるか考えない。**
   更新の失敗を追うログを入れた版を配っても、入れた時点で最新版になり
   「更新するものが無い」ためダウンロードが走らず、ログを採れない。
   診断のための変更が、診断できる状態を壊していた。

10. **アニメーションの完了前に実測する。**
   `transition` が 160ms なのに 150ms で読む、200ms なのに 120ms で読む。
   手元では偶然すり抜け、CIで落ちる。固定の待ち時間ではなく、
   収束を待つ（`waitForFunction`）こと。

11. **手元で必ず成功することを、どこでも成功することとして扱う。**
   会社のPCで一度も更新できなかった原因はGitHub APIの問い合わせ上限（IPごと1時間60回）で、
   共有IPの環境では常に上限に達していた。自宅は専有IPなので永久に再現しない。
   「家では動く」は反証にならない。あわせて「上限に達した」を一時的なものと決めつけない
   （上限に当たるのが常態の環境がある）。

12. **要点だと自分で書いたことを、その経路で確かめない。**
   「通信を確かめる」は「最新版でも押せること」が存在理由なのに、まさに最新版のときに
   `DownloadUrl` が空になって動かなかった。8と同じ形の抜けを、8を書いた直後にまた作っている。
