# 会社のPCで更新のダウンロードだけが失敗する

対応した版: 次の版（原因の特定はこれから）

利用者からの報告。自宅では必ず成功するのに、会社のPCでは一度も更新できない。
「新しい版があること」までは分かるが、ダウンロードが進まない。

## まず分かったこと: 今のログでは原因を追えない

手元にある16本のログ（すべて自宅のPC）を調べたところ、ダウンロードの失敗は
1件も記録されていなかった。「更新のダウンロード」という行は2つだけで、どちらも
2026-08-23 の成功例だった。会社のログを採る前に、**採っても原因が分からない**
状態だと分かった。

足りなかったものは3つ。

### 1. 内部例外を捨てていた

`Logger.WriteException` は、いちばん外側の例外の型名・メッセージ・スタックだけを
出していた。ところがネットワークの失敗は、本当の理由がInnerExceptionに入る。

```
HttpRequestException「送信できませんでした」
  └ SocketException「接続が拒否されました」          ← プロキシ/ファイアウォール
HttpRequestException「SSL接続を確立できませんでした」
  └ AuthenticationException「リモート証明書が無効」  ← 会社のSSL検査
    └ Win32Exception「信頼されないルート証明書」
```

外側だけでは「HttpRequestException」としか分からない。連鎖をすべて出すようにした
（`ExceptionDetail`、テスト8件）。HTTPの状態コード（403=拒否 / 407=プロキシ認証）も
持っていれば添える。

### 2. ダウンロードの失敗をその場で記録していなかった

`DownloadAsync` は `catch { TryDeleteDirectory(directory); throw; }` としており、
記録を残さずに投げ直していた。呼び出し元のログには「更新の適用に失敗」としか
残らず、**繋がらなかったのか途中で切れたのかも分からなかった**。
失敗時に受信済みバイト数を添えて記録するようにした。

### 3. どこへ繋ぎに行ったのかが分からなかった

`github.com/.../releases/download/...` は `objects.githubusercontent.com` へ
転送される。会社のプロキシが `github.com` だけを許可していれば、確認は通って
ダウンロードだけ落ちる。報告の症状とちょうど合う。

応答の状態コード・転送先の最終URL・Content-Type・Via ヘッダを記録するようにした。
Content-Type が `text/html` なら、中身がZipではなくプロキシのエラーページに
すり替わっている。あわせて、プロキシを経由するかどうかも起動ごとに1回残す。

## あわせて直したもの

### Zipを取りに行くのにJSONを要求していた

`HttpClient` の既定ヘッダとして `Accept: application/vnd.github+json` を付けており、
Atomフィード以外のすべての要求——Zipのダウンロードを含む——に乗っていた。
GitHub自体は無視するが、中身とヘッダの不一致を見る経路を通るときに弾かれる余地を
残す必要は無い。要求ごとに適切なAcceptを付けるようにした。

### 失敗すると手で入れ替える導線が消えていた

更新に失敗した状態（`updatePhase === "failed"`）では、エラーメッセージだけを出して
「リリースページを開く」ボタンを消していた。**自動更新が通らない人ほど導線を
失っていた**ことになる。仕様書はもともと手動更新を許容しているのだから、
失敗したときこそ出すべきだった。失敗時にもボタンと、Zipを取って置き換える旨の
案内を出すようにした。

## 会社のログの読み方

`更新のダウンロード開始` の直後に出る行を見る。

| 出るもの | 意味 |
|---|---|
| `応答 403 Forbidden` | 経路上で拒否されている |
| `応答 407 ProxyAuthenticationRequired` | プロキシの認証が通っていない |
| `Content-Type=text/html` | Zipではなくプロキシのエラーページが返っている |
| `転送先=https://objects.githubusercontent.com/...` が出ない | 転送前に止められている |
| `AuthenticationException` / 証明書 | SSL検査に引っかかっている |
| `受信済み 0バイト` | 接続の時点で失敗 |
| `受信済み ○○バイト`（途中） | 大きいファイルが通らない／切られている |
| `更新の通信: プロキシを経由する(...)` | 社内プロキシ経由であることの確認 |

原因が分かるまで手を入れない。ここまでは「分かるようにする」ための変更だけで、
通信のやり方自体は変えていない（プロキシ認証の設定を足す等は、ログを見てから）。
