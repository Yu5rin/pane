# 折りたたみマーカー(+/−)が見えないことがある不具合の調査記録

このファイルは消さずに残す(過去2回この作業が中断しているため、分かったことを
随時書き足す指示による)。

## 対象

`src/editor.js` のコードモード折りたたみマーカー(`.cm-fold-marker2`)。実機から
「＋/−の記号が見えないことがある」との指摘。

## 環境メモ

- 作業ディレクトリ: `/workspace/pane`(ブランチ `claude/pane-phase-1-setup-87833g`、
  `origin/main` の `ff4ed38` と同じ位置から開始)。
- `npm run build` → `dist/` を `python3 -m http.server 8195` で配信し、
  Playwright(`.verify-codefold.mjs` や `.repro-*.mjs`)で検証する、という前回までの
  やり方をそのまま踏襲した。
- このサンドボックス(Linux)には `JetBrains Mono` も `BIZ UDゴシック` も
  インストールされていない(`fc-list` で確認)。フォント関連の検証(下記②)は
  Windows実機の値を直接は確認できていない点に注意。

## 結論(先に書く)

**原因は特定できた。主原因は「配色のコントラスト不足」で、これは修正済み。**
副次的に「横スクロール時にマーカーが画面外へ流れて見えなくなる」ことも再現できたが、
これは修正していない(理由は下記)。

## 主原因: マーカーの「記号」と「地(塗り)」自身のコントラスト不足

### 何が起きていたか

`FoldOpenMarkerWidget` / `foldOpenMarkerTheme`(editor.js 3684行付近、修正前)は
以下の配色だった。

```
color: var(--paper)          // 記号("+" / "−")の色
border: 1.5px solid var(--ink-sub)
backgroundColor: var(--ink-sub)  // マーカー自身の地(塗り)
```

`--ink-sub` は `src/style.css` / `src/themes.css` で「本文(`--paper`)の上に乗る、
控えめな補助文字の色」として各テーマ個別にチューニングされた変数(ガター行番号・
ヒント文字・無効メニュー項目などに使用)。これを「記号(`--paper`)を乗せる地の色」
として流用していたため、記号色と地色そのもののコントラスト比が一部テーマで低かった。

### 実測値(修正前、`.repro-scratch2.mjs` / `.contrast-ink-scratch.mjs` で実測)

9テーマそれぞれで「記号色(--paper) vs 地色(--ink-sub)」のコントラスト比:

| テーマ | 比 | WCAG AA(4.5:1)判定 |
|---|---|---|
| default-light | 4.87 | ○ |
| default-dark | 6.71 | ○ |
| sepia | 4.44 | **×(僅かに不足)** |
| github | 6.11 | ○ |
| solarized-light | 4.13 | **×** |
| nord | 9.25 | ○ |
| dracula | 7.36 | ○ |
| solarized-dark | 4.75 | ○ |
| night | **3.24** | **×(大きく不足)** |

9テーマ中3テーマ(sepia / solarized-light / night)でWCAG AAの通常文字基準
(4.5:1)を満たしていなかった。特に night は 3.24:1 しかなく、実機の「見えない
ことがある」報告と一致する(「ことがある」=テーマに依存して起きたり起きなかったり、
という報告文言とも整合する)。

この記号は 12px・font-weight 800 で描画されており、WCAGの「大きな文字」の緩和
基準(太字なら概ね18.66px以上)を満たさないサイズのため、必要なのは3:1ではなく
4.5:1。

### なぜ既存の検証(`.verify-codefold.mjs` (T)節)で見つからなかったか

(T)節は「マーカーの地色(旧: --ink-sub)が周囲の背景(--paper)から浮いて見えるか」
(`fillRatio`)だけを3.0:1の閾値で検証していた。これは「マーカーの四角自体が
背景から浮いて見えるか」の確認であり、肝心の「記号そのものが地の色の上で読めるか」
(記号色と地色自身のコントラスト、`textRatio`)は一度も検証していなかった。
さらに3.0:1という閾値自体も、WCAGの「大きな文字」用の緩い基準を(12pxの小さい
記号に対して)誤って適用したもので、本来必要な4.5:1より緩かった。

editor.js側のコメント(3025行付近、旧文言)にも「9テーマでコントラスト比3.0以上を
確認済み」とあり、この「3.0」という閾値そのものが、そもそも小さな太字記号には
本来当てはまらない基準だったことが分かる。

### 直した内容

`src/editor.js`:
- `foldOpenMarkerTheme`(3684行付近、`.cm-fold-marker2`)の
  `border`・`backgroundColor` を `var(--ink-sub)` → `var(--ink)` に変更。
  `color`(記号色)は `var(--paper)` のまま変更していない。
- 併せて、3018行付近・3690行付近の設計コメントを、上記の経緯・理由が分かるように
  書き換えた(旧コメントの「3.0以上を確認済み」という誤った前提の記述も、経緯として
  読めるように更新)。

`--ink` は仕様書10.2節の6変数の1つ(本文の主色)で、新しい色を導入していない
(CLAUDE.mdの配色制約を守っている)。`--ink`/`--paper` のコントラスト比を9テーマで
実測したところ、最小でも5.61:1(solarized-dark)、他は6〜16:1と、すべてAA基準
(4.5:1)を余裕を持って超える(`.contrast-ink-scratch.mjs` で実測)。`--ink` は
本文の主色として「常に`--paper`の上で高いコントラストを保つ」ことがテーマ設計上
保証されている変数のため、この用途(記号を乗せる地の色)に適している。

ホバー時の配色(`color: var(--paper)`, `backgroundColor/borderColor: var(--accent)`)
は今回変更していない。実測すると sepia(3.36)・solarized-light(3.41)・
solarized-dark(4.08、僅差)でAA未満だが、これは `docs/調査記録/点検-見た目とUI.md` に別途記録されている
「`--accent` を背景色として使う組み合わせ全般(ダイアログの主ボタン等12箇所)が
一部テーマでAA未満」という、フォールドマーカーに限らないアプリ全体の既知の課題と
同根であり、今回のチケット(フォールドマーカーの記号が見えない)の範囲外と判断し、
あえて触れていない。

### 追加した検証

`.verify-codefold.mjs` に (Z)節を追加(A〜Yはすでに使用済みのため次の空き文字)。
9テーマそれぞれで「記号色(--paper)と地色(--ink)自身」のコントラスト比が
4.5:1以上であることを検証する。

**修正前のコードに対してこの(Z)節を実行し、実際に落ちることを確認済み**
(下記の実測値、`git stash` でeditor.jsだけ旧版に戻して確認):

```

NG   (Z) solarized-light: 実測=4.13
NG   (Z) night: 実測=3.24
合計: OK 271 / NG 3
```

修正後は9テーマ全部でOK(最小 solarized-dark 5.61、night 6.09)。

## 副次的な原因(調査したが、今回は修正していない): 横スクロールでマーカーが画面外へ流れる

### 再現内容

`.repro-scroll2.mjs` で再現: 折り返し表示をOFFにし、長い行を含む文書を開いた状態で
`.cm-scroller.scrollLeft` を進めると、短い行(例: `function outer() {`)にある
マーカーもテキストと一緒に横スクロールして画面外(`rect.left` が負の値)へ流れ、
完全に見えなくなる。

原因: `FoldOpenMarkerWidget` のアンカー(`.cm-fold-open-anchor`)は
`line.from`(行頭)に挿入されるインライン要素で、`.cm-content` の通常の
テキストフロー内にある。マーカー自身はこのアンカーに対して
`position: absolute` で「本文エリアの左端から固定5px」の位置に置かれているが、
これは「インデントの深さに関わらず同じ位置」という意味の"固定"であって、
"画面(ビューポート)に対して固定"ではない。アンカーごと横スクロールで画面外に
押し出されれば、マーカーも一緒に見えなくなる。

### なぜ今回は直していないか

1. **既定では発生しない**: `wordWrapOn` の既定値は `true`(`src/main.js:331`)。
   折り返し表示がONの間は横スクロール自体が起きないため、この経路には
   到達しない。ユーザーが明示的に折り返しをOFFにし、かつ画面外まで
   横スクロールしたときだけ発生する。
2. **単純な修正では直らないことを実験で確認済み**: 前回のエージェントが残した
   `.repro-sticky.mjs` で「アンカーに `position: sticky; left: 0` を当てるだけ」を
   試したが、`scrollLeft=400` にしてもマーカーは画面外(`rect.left: -20`)のままで、
   stickyは効かなかった。今回改めて実行し再確認した。
   - 原因の見立て: アンカー(`.cm-fold-open-anchor`)は `display: inline-block;
     width: 0`。sticky位置計算の基準となる「containing block」がこの幅0の
     アンカー自身になってしまうと、sticky可動域が実質無いに等しく機能しない
     可能性が高い(`.cm-line` 自体は最長行に合わせて実測2844px幅まで伸びている
     ことは確認済み=`.contrast-linewidth-scratch.mjs`。つまり「幅は足りている」
     が、幅0のアンカーを経由する現在の構造では届いていない)。
   - 正しく直すには、マーカーの水平位置を「アンカー基準のabsolute」から
     「`.cm-scroller`基準でどこかにsticky」という別の仕組みに設計し直す必要が
     ありそうだが、それには行番号ガター幅(可変)の扱いや、
     `computeFixedMarkerLeftPx` に依存している既存の検証4本
     (`.verify-codefold.mjs` (P)(T)(Z)節、`.verify-hang-code.mjs`、
     `.verify-shellfold.mjs`、`.verify-codecopy-activeline.mjs`)への影響範囲が
     大きく、片手間の修正では正しく検証しきれないと判断した。
3. **今回のチケットの文言と直接一致するのは主原因の方**: 実機の指摘は
   「＋/−の**記号**が見えないことがある」であり、これは「記号色と地色自身の
   コントラスト」が原因の主原因の方が文言に忠実に一致する。横スクロールは
   マーカーの四角ごと消えるので、性質が異なる(見た目の症状としてはより
   極端=全く見えない、だが発生条件が既定外)。

**残る疑問・次に手を付けるならここから**: 横スクロール対応をやるなら、
`.cm-fold-open-anchor` 自体を width:0 のままにせず、`.cm-line` の直接の子として
`position: sticky` を持つラッパー要素に置き換える設計が候補。ガター幅は
`getComputedStyle`で実測しJSでinline styleへ焼き込む(既存の`contentPaddingLeftPx`
実測と同じ手法)。着手する場合は上記4本の検証ファイルを先に読み、期待値
(「scrollLeft=0のときのマーカー位置」)を保ったまま「scrollLeft>0でも画面内に
留まる」ケースを追加すること。

## 調べて「原因ではない」と判断した項目(優先候補として挙げられていたもの)

- **① 15px枠に12px/800weightの記号がはみ出す/潰れる**: `.repro-scratch.mjs` (5)で
  実測。`offsetWidth: 15`, `scrollWidth: 13` で枠内に収まっている(はみ出し無し)。
- **② U+2212がフォールバックで豆腐/別字形になる**: このサンドボックスには
  `JetBrains Mono`も`BIZ UDゴシック`も無く(`fc-list`で確認)、実際に使われた
  フォールバックフォントでは正しく描画された(①のとおり収まっている)。
  **ただしWindows実機の`Consolas`/`Segoe UI`等での見え方はこの環境では検証
  できていない**。U+2212(MINUS SIGN)はWGL4文字集合に含まれ主要なWindows
  搭載フォントで概ねサポートされているはずだが、未検証のまま。もし実機で
  再現するなら、フォールバックの並び(`--font-mono`, `src/style.css:135`)の
  見直しが次の一手になる。
- **④ フォントサイズ8〜40pxでの釣り合い**: `.repro-scratch.mjs` (4)と
  `.contrast-fontsize-scratch.mjs`で実測。8pxでは行の高さ(15.6px)とマーカー
  (15px固定)がほぼ一致し重なりは無い。40pxでは行に対してマーカーが相対的に
  小さくなるだけで、見えなくなるわけではない(単に小さい)。「見えない」という
  報告とは一致しないため、今回は対応していない。
- **⑤ 選択範囲・検索ヒット・アクティブ行のハイライトがマーカーの上に乗る**:
  `.repro-scratch.mjs` (1)(2)(3)で実測。いずれも `document.elementFromPoint`で
  最前面がマーカー自身であることを確認(`zIndex: 2`で足りている)。
- **⑥ マーカーの地色と、実際に乗っている背景(--paperか--code-bgか)のズレ**:
  `.contrast-bg-scratch2.mjs`で実測。コードモードの本文の実際の背景は`body`要素の
  `--paper`(既定ライトで`rgb(251,251,250)`)であり、`.cm-content`/`.cm-editor`
  自体は透過。マーカーのCSSが前提にしている背景(`--paper`)と実際に乗っている
  背景は一致していた。`--code-bg`はMarkdown WYSIWYGのコードフェンス専用で、
  コードモードの折りたたみマーカーには関係しない。

## 第2幕: 会社の実機で再発。今度はフォントだった (2026-09-11, v1.1.9)

上の修正（配色を `--ink` に変えた）を入れたあとも、会社のPCで「＋−が表示されていない」
という報告が出た。**同じ症状に見えるが、原因はまったく別だった。**

### 決め手は利用者の指摘だった

私は「全部のマーカーが見えていない」と思い込み、フォントに記号が無くて豆腐になっている、
という見立てで調べていた。開発者ツールの Rendered Fonts を見てもらったところ、

```
Family name: BIZ UDGothic
PostScript name: BIZ-UDGothic-Bold
Font origin: Local file(1 glyph)
```

**1 glyph** ＝ 文字はちゃんと描けていた。豆腐ではない。見立ては外れ。

さらに利用者から **「先頭の1つは描写できているので、それが原因ではないでしょ」** と
指摘された。同じ色・同じフォント・同じ大きさで1つ目だけ描けているなら、色でも
フォント名でもサイズでもない。私は「全部見えていない」という誤った前提で、見当違いの
ところを掘っていた。

### 分かったこと

同じログにこう出ていた。

```
等幅フォント: "HackGen35" を適用
```

設定された等幅フォントは **HackGen35**。ところが記号を実際に描いたのは **BIZ UDGothic**。
つまり **HackGen35 に "−"(U+2212 MINUS SIGN) が無く、日本語フォントへ落ちていた**。

`+`(U+002B)はほぼどのフォントにもあるので落ちない。**記号によって描画フォントが
変わっていた**。日本語フォントの記号は全角幅で設計されているため、15pxの小さな枠に
収めると線の太さも位置も揃わない。

「1つだけ見える／他は見えない」という見え方の細部までは詰めきれていないが、
**文字で描いているかぎり、利用者がどの等幅フォントを選ぶかで字形が変わり続ける**
という構造そのものが原因だった。

### 直したこと

記号をSVGにした（`FOLD_MARKER_SVG_MINUS` / `FOLD_MARKER_SVG_PLUS`）。フォントに一切
依存しなくなる。線幅2.55は、viewBox16を11pxで描いたときに仕様書10.1節の基準
（16pxで線幅1.75）と同じ太さに見える値。色は `stroke="currentColor"` なので、
テーマごとの配色（第1幕で直した `--ink` / `--paper`）はそのまま効く。

そもそもCLAUDE.md・仕様書10.1節は「アイコンと記号はすべてSVG」としており、
**ここだけが例外**だった。第1幕で配色を調べたとき、この方針違反に気づいていれば
2回目は起きなかった。

`.verify-codefold.mjs` の(J)節に「マーカーの中に文字が入っていないこと」を追加した。
文字に戻すと3件落ちることを確認済み。

### 繰り返さないために

- **利用者の観察を、自分の思い込みより優先する。** 「先頭の1つは描けている」という
  一言が、色・フォント・サイズをまとめて否定していた。私はスクリーンショットを
  「全部見えていない」と読み違えたまま、3回別の仮説を立てて回り道をした
- **同じ場所で2回目の不具合が出たら、1回目に直した軸とは別の軸を疑う。**
  1回目は配色、2回目はフォント。同じ「見えない」でも原因は別だった
- **方針違反は、いずれ不具合として出てくる。** 「記号はすべてSVG」という決まりが
  あったのに文字で描いていた箇所が、まさにそこで壊れた
