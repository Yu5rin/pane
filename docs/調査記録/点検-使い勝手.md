**メニューバーにもコマンドパレットにも無い操作**（右クリックまたは画面上のボタンだけ）: 元に戻す／やり直す、水平線、タスクリスト（main.js:1704-1705, 1815-1817）、テーマ切替(ライト/ダーク)、表の行・列の挿入/削除/配置(main.js:1738-1751)、リンクの編集/解除、画像のパス編集/削除、言語を選択（コードモード）。

Windowsの慣習との食い違い（Typora準拠のため意図的なものが多い。困る順）:
- 印刷が Ctrl+Alt+P。Ctrl+P はクイックオープン（メモ帳・Word・ブラウザはすべて Ctrl+P=印刷）
- 折り返し表示にキーが無い（VS Code: Alt+Z）
- 元に戻す/やり直しが編集メニューに無い（メモ帳・Word・VS Codeはすべて編集メニュー先頭）
- Ctrl+Shift+K（VS Code: 行削除）／Ctrl+/（VS Code: コメント切替）／Ctrl+Shift+[ ]（VS Code: 折りたたみ）は Typora と同じ割当。コードファイルを VS Code 感覚で開く人は戸惑うが、設定「キーボード」で変えられるので【低】

## 2. 指摘（ユーザーが困る順）

### 【高】

- **H1. 「開く」ダイアログのフィルタにコードファイルが無い。** Pane/MainForm.cs:1910 `Filter = "Markdown / テキスト (*.md;*.markdown;*.mdown;*.txt)|...|すべてのファイル (*.*)"`。README・取扱説明書1章で「.js .py .cs .json などのコードエディタとしても使える」と謳っているのに、Ctrl+O では毎回「すべてのファイル」へ切り替えないと .js 等が見えない。→ src/file-types.js の約60種の拡張子から「コード」フィルタを1つ生成して2番目に置く（保存側 BuildSaveFilter(MainForm.cs:1995-2010) も同様）。
- **H2. サイドバー「ファイル」タブの説明が実装と逆で、名前も3通り。** 実装は「読み込んだフォルダ内のファイルの平坦な一覧」（src/sidebar.js:408-455 renderFiles、仕様書 S-02）。ところが取扱説明書3.3「最近開いたファイルを新しい順に一覧表示」、同6章「ファイル(最近使ったファイル)パネル」、src/tooltips.js:152-155「最近使ったファイルの一覧を表示します」「最近開いたファイルを新しい順に一覧表示します」と、全部「最近使ったファイル」と説明している。さらに表示メニューでは「記事リスト」（commands.js `view.articleList`）、タブは「ファイル」（index.html title="ファイル"）、仕様書2.8は「ファイルリスト」。最近使ったファイルの実体は「ファイル」メニュー→「最近使ったファイル」サブメニュー（file.recentFiles）。→ 名前を「ファイル一覧」等の1つに統一し、説明書・ツールチップを実装に合わせて書き直す。
- **H3. 「元に戻す」「やり直す」がメニューバー「編集」に無い。** commands.js の Edit 節に undo/redo が無く、右クリック（main.js:1704-1705, 1823-1824）と入力欄用（commands.js:750-751）だけ。コマンドパレットからも呼べない。仕様書10.1「メニューバーと機能を重複させ、どちらか一方だけでも全操作に到達できる」に反する。マウス派の人は右クリック以外に手段が無い。
- **H4. 設定「自動保存」のツールチップが実態と違い、誤解を招く。** src/tooltips.js:361「編集中の内容を自動的に上書き保存します」。実際は元ファイルには触れず %LOCALAPPDATA%\Pane\autosave\ へスナップショットを書く方式（Pane/AutoSaveService.cs:17-19、取扱説明書4.6も同じ）。「勝手に上書きされる」と思ってオフにする人、「もう保存された」と思ってCtrl+Sを押さない人の両方が出る。settings.js:1311 のラベル「自動保存」自体も「未保存内容のバックアップ」等に改めたい。
- **H5. Ctrl+N「新規作成」と Ctrl+Shift+N「新しいウィンドウ」が完全に同じ動作。** Pane/MainForm.cs:1423-1429 で `case "new"` と `case "new-window"` が同じ `_requestNewWindow?.Invoke(null)`。メニューに同じ結果の項目が2つ並び、取扱説明書6章にも違いの説明が無い。→ 片方を消すか、「新規作成」は現在ウィンドウで新規文書（未保存なら確認）にする。

### 【中】

- **M1. 印刷 Ctrl+Alt+P／Ctrl+P はクイックオープン。** commands.js file.print / file.quickOpen。フォルダを読み込んでいない状態（無題の新規文書）では Ctrl+P を押しても何も起きない（enabled=false のためログだけ。commands.js:516）。仕様書 F-13 が「別キー」を求めているので設計どおりだが、Windows では Ctrl+P=印刷が最も強い慣習。せめてフォルダ未読込時の Ctrl+P は「フォルダが読み込まれていません」を出すか印刷に倒す。
- **M2. 折り返し表示の切替が保存されない＋キーが無い。** src/main.js:331 `let wordWrapOn = true;` 固定、toggleWordWrap(main.js:1521-1525) は bridge へ何も送らず、apply-settings にも wordWrap は無い。ログを開くたびに折り返しを切るような人は毎回ステータスバーをクリックすることになる。設定「コードブロックの長い行を折り返し」(settings.js:1345 codeAutoWrap) は別物（コードブロック内のみ）で、tooltips.js:214 は両者を「既定値」として結び付けて説明しており紛らわしい。
- **M3. エクスポート8項目がファイルメニューに平置き。Pandoc未導入の理由が見えない。** commands.js file.exportPdf〜exportTextile。無効化の理由 note「Pandoc未導入」は Pane/NativeMenu.cs:119-121 で ToolTipText に入れているだけで、WinForms の無効(Enabled=false)なメニュー項目にはツールチップが出ない。取扱説明書4.7を読まない限り「なぜ選べないのか」が分からない。→ 「エクスポート」サブメニューにまとめ、ラベル自体に「(Pandocが必要)」を含める。
- **M4. 表示メニューが32項目。** 折りたたみ関係13項目（再帰2＋レベル1〜5＋コメント1＋基本4）がサブメニュー化されず、Markdownモードでは全部グレー表示のまま並ぶ。commands.js の該当コメントにも「ウィンドウを小さくすると項目数の多いメニュー(例: 表示メニュー20項目)が画面外へはみ出す」とあり、ネイティブ化で凌いでいる。→ 「折りたたみ」「編集モード」「文字サイズ」のサブメニューへ。
- **M5. 「水平線」「タスクリスト」がメニューバー・コマンドパレットに無い。** main.js:1815, 1817 の右クリック「段落」サブメニューのみ（para.listCheck は contextOnly で「タスクリストに変換」）。取扱説明書5.2はチェックリストを記法でしか説明していない。Typora の段落メニューには両方ある。
- **M6. テーマの変更が遠い／ボタンの副作用が見えない。** 配色プリセットは 設定(Ctrl+,)→外観→テーマ→保存 の4手。メニューバー右端ボタン(main.js:3110-3118)はライト/ダークのトグルのみで、押すと theme が「システムに合わせる」から固定値へ変わり（set-theme）、以後OSの切替に追従しなくなる。その旨は tooltips.js:114（標準以上の詳しさ）にしか無い。コマンドパレットにも「テーマ」の項目が無い（commands.js に無い）。
- **M7. Alt 単押しでメニューバーが消える。** commands.js:653-662。Windows では Alt=メニューにフォーカス。何かの拍子に Alt を押してメニューバーが消えると、戻し方（もう一度Alt）が画面のどこにも書かれていない（取扱説明書3.1にはある）。Typora の挙動に合わせた仕様（仕様書10.1/10.4）ではあるが、初見の人は「メニューが壊れた」と感じる。
- **M8. コマンドパレットの検索がメニュー名の英語キーで照合される。** commands.js:292 `c.menu.toLowerCase().includes(q)` の menu は "File"/"Edit"…。表示は「ファイル: 開く」なのに「ファイル」と打っても絞り込めず、"file" と打つと絞り込める。
- **M9. 設定画面の検索は「カテゴリを絞る」だけ。** tooltips.js（settings-search）「一致するカテゴリだけを左側のナビゲーションに残して絞り込みます」、取扱説明書7章も同じ。11カテゴリ・約100項目あるのに、絞ったカテゴリ内で該当項目が光らないので結局スクロールして探す。

## 5. 発見しやすさ

- 初回起動時の案内が無い。起動すると空の本文だけ（index.html に歓迎表示・空状態のヒントは無い）。「F1で取扱説明書」「Ctrl+Shift+Pでコマンドパレット」「.js を開けばコードエディタになる」は README と説明書に頼っている。
- 便利だが入口が1つしか無いもの: コマンドパレット(Ctrl+Shift+Pのみ。メニュー・ボタンに無い)、テーマ切替(右端ボタンのみ)、表の行列操作(セル上ボタン/右クリック)、元に戻す(右クリック)、水平線・タスクリスト(右クリック)、コードブロックのコピー(ホバーで現れるボタン)、文字数の詳細(ステータスバーの文字数をクリック)、言語の選び直し(ステータスバーのモード表示をクリック)。
