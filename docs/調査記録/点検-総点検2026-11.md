# 総点検（2026-11）— 不具合・操作性・見た目

「全体的なバグ出し、操作性の悪さ、メニューの見直しを行い、製品版のクオリティまで高める」という
依頼を受けて、4つの観点（JS側の編集機能／操作とメニュー／C#側／見た目）で点検した記録。
点検はコードを変更しない形で行い、見つかったものを**自分で再現してから**直した。
再現できなかったもの・実機でしか確かめられないものは、そう書いてある。

回帰の検査は `.verify-editing-fixes.mjs`（新設）と `.verify-late-blocks.mjs`（新設）、
`.verify-code-colors.mjs`・`.verify-help.mjs`（追記）、`Pane.Tests`（追記）にある。

## 直したもの

### 編集（JS側）

| 何が起きていたか | 原因 | どう直したか |
|---|---|---|
| 開いた文書の後半（先頭から約3,000文字より後ろ）にある表・`[toc]`・Mermaid・生HTMLが、記法のまま表示される。クリックしても直らない | CodeMirrorは文書を作った時点では先頭の約3,000文字しか解析せず、残りは裏で進める。表などの一覧は「文書が変わったとき」にしか作り直していなかった | 解析が進んだ（構文木が伸びた）ときにも作り直す。アウトラインも同じ理由で途中までしか並ばなかったので、同じ合図で描き直す |
| 太字・斜体・コードの直後で日本語を変換して確定すると、**直前の文字が消える**（「これは\*\*太字\*\*」→「これは\*\*\*\*に日本語」） | 変換中の1文字ごとにライブプレビューの装飾を作り直しており、カーソルの隣の記法の表示/非表示が切り替わって、ブラウザが変換中の文字を置いたDOMを見失う | 変換中は作り直さず、今ある装飾の位置だけをずらす。確定したら作り直す |
| 太字などで終わる行で End キーや行末のクリックをしてから続きを書くと、**続きまで太字になる** | 隠れている閉じ記号（`**`）は幅が無いので、カーソルが記号の手前に入る | 外から移動してきて、カーソルの先が行末まで閉じ記号だけなら行末へ進める。装飾の中を矢印キーで動いているときは何もしない |
| セルに `\|` を書いた表が、表から離れた瞬間に列の増えた形へ書き換わる | 行を単純に `\|` で割っていた（割る・セルの位置を求める・何列目かを数える、の3か所とも） | 区切りを求める関数を1つにし、3か所すべてでそれを使う。コードの中の `\|` は GFM でも区切りなので、そのまま |
| `file_name.txt`→`file_name.txt_`、`2 * 3 = 6`→`2 * 3 = 6*`、`10~20`→`10~20~`、文中の `**太字**`→`**太字***` | 記号の自動補完が「直後に同じ記号があれば乗り越える、無ければ対で入れる」だけだった | 強調の開き側になりえない場所では対にしない（決まりは `src/editor.js` の `MD_PAIR_CHARS` の説明に4つ） |
| 正規表現オフの検索・置換で `\n` `\t` が改行・タブとして働く（`C:\new` が見つからない） | CodeMirrorの検索は、明示しないと検索語のエスケープを読み替える | 正規表現がオフのときは「そのままの文字」として渡す |
| Webページやメールの本文を貼ると、段落・見出し・リストが1行につながる。入れ子のリストが親の項目とつながる | 全体を包む `div` を1つの段落として読んでいた。リストの項目の中身をすべて1行として読んでいた | ブロックを含む `div` は中へ降りる。入れ子のリストは字下げして続ける。表のセルの `\|` と改行も崩れないようにした |
| 表のセルへ複数行を貼ると表が崩れる | 表の1行は文書の1行なので、改行が入ると行が切れる | 文書を書き換える直前の1か所で、セルの中への貼り付けだけ改行を空白にする（入口ごとに直さない。README の「繰り返し出てきた誤り」8） |
| アウトライン・目次に `**重要**` のように記号ごと出る | 見出しの文字をそのまま並べていた | 表示する文字からインラインの記法を取り除く。スラグ（リンク先の名前）は変えない |
| 取扱説明書に `**` が記号のまま13か所表示されている | `**「設定名」**を` のように、かぎ括弧や句点と隣り合う `**` は、Markdownの決まりでは太字の開き・閉じにならないことがある | 原稿で `**` をかぎ括弧の内側に、句点を `**` の外側に置いた。`.verify-help.mjs` で残っていないことを確かめる |

### 操作

| 何が起きていたか | 原因 | どう直したか |
|---|---|---|
| Ctrl+Shift+1〜3（サイドバーの切り替え）、Alt+Shift+5（取り消し線）が効かない | Shiftを押していると `e.key` は記号（`!` `%`）になる。数字は `0` だけを物理キーで見ていた | 数字はすべて物理キーで見る。設定のキー登録も同じに直した |
| コードモード・プレーンテキストで Ctrl+B や Ctrl+1 を押すと、JSONやソースの中に `****` や `# ` が書き込まれる | 段落・書式のコマンドがモードを見ていなかった | Markdownの記法を書き込むコマンドは Markdown の文書でだけ有効にする（メニューでも灰色）。インデントは残す |
| コマンドパレットで「最近使ったファイル」を選ぶと何も起きない（内部ではエラー） | 実行する中身を持たない項目（下の階層を開くだけ）まで並べていた | 実行できるものだけを並べる。あわせて、メニューの名前（「表示」など）とショートカットでも探せるようにした |
| ステータスバーの「Markdown」を押しても何も起きない | コードモードのときだけ反応する作りだった | Markdown・プレーンテキストではモードを選ぶメニューを出す |

### C#側

| 何が起きていたか | 原因 | どう直したか |
|---|---|---|
| 保存に失敗しても画面に何も出ない | ログに書くだけだった | 理由を添えて知らせる。内容は失われていないことと、名前を付けて保存への案内も書く |
| 起動が重いときに2つのファイルを同時に開くと、プロセスが2つになる | 2つ目以降の起動を受ける口を、最初のウィンドウを作り終えてから開けていた。2つ目は口が開くのを2秒しか待たない | 口を先に開ける。ウィンドウができる前に届いた要求は控えておき、できてから開く |
| 同じファイルが2つのウィンドウで開ける（最近使ったファイル・サイドバー・クイックオープン・検索結果から） | 重複の確認が「新しいウィンドウで開く」経路にしか無かった | 実際に読み込むところ（`OpenFile`）で確かめる |
| ネットワークドライブやUSBメモリで「ごみ箱へ移動」すると、完全に削除される | そこにはごみ箱が無く、Windowsは黙って消す | ごみ箱の無い場所では、元に戻せないことを伝えてもう一度確かめる |
| PDFの書き出しに失敗しても気づけない | 結果（成功したか）を見ていなかった | 失敗なら知らせる |
| 他のアプリが書き込み中のファイル（ログなど）が開けない | 「他の誰も書き込んでいないこと」を求める開き方だった | 相手の書き込みを妨げない形で読む |
| 更新の入れ替えが最初の一歩で失敗すると、手つかずの `dist` を消してしまう | 失敗したら無条件に今の `dist` を消していた | 新しいものを置き始めたあとの、置きかけのものだけ消す（`UpdateRollbackLogic`） |

## 点検の途中で、自分が入れた誤り

- **後半の表を描くための修正で、Markdownとコードモードの切り替えが落ちるようになった。**
  「一覧が作り直されたか」を、切り替えの前後の状態から読んで比べる処理を入れたが、
  コードモードにはその一覧が無い。新しく作った検査（Markdownの文書だけを開く）は通り、
  コードモードを開く既存の検査（`.verify-code-colors.mjs`）で見つかった。
  直した機能を使わないモードでも回すこと（README の「繰り返し出てきた誤り」29）。
- **日本語入力の不具合を確かめる検査を書いたら、別の不具合（行末で止まる位置）を先に踏んだ。**
  End キーで行末へ行ったつもりが閉じ記号の手前にいて、変換の結果ではなく位置のせいで
  太字の中に入っていた。普通に1文字打って確かめ、原因を分けた。両方とも直した。

## 利用者に選んでもらって変えたもの

見た目や操作が変わるものは、案を出して選んでもらってから入れた（2026-11-14）。

### メニューの組み替え

「表示」に32項目、「編集」に26項目が1列に並んでいた。Markdownの文書では使えない折りたたみの
12項目が「表示」の半分近くを占めていた。

- 並びを `src/commands.js` の `MENU_LAYOUT` の1か所で決める形にした。以前は「コマンドの定義の順＝
  メニューの並び」だったので、並びを直すにはコマンドの定義を動かすしかなかった
- コマンドの id とショートカットは変えていない（キー割り当ての設定が id を見ている）
- 並びを別に持つと「コマンドは足したがメニューに書き忘れた」が起きる。`.verify-menu-layout.mjs` が、
  メニューに属するのに配置に無いコマンド・実在しない id・同じ id の重複・上の階層の項目数を見る
- 下の階層の項目も、上の階層と同じ作り方で描く（ショートカット・チェック・無効の表示が出る）。
  以前の下の階層は「最近使ったファイル」専用で、名前しか出せなかった
- ヘルプメニューを足した。取扱説明書（F1）・ショートカット一覧・コマンドパレット・バージョン情報は、
  それまで右上のボタンかキーを知っている人にしか届かなかった
- 「新しいタブ」は、タブ形式でないときは並べない（既定では一度も押せない項目が3番目にあった）
- メニューの中身を平らに探していた既存の検査（折りたたみ・エクスポート・タブ）は、下の階層も
  探すように直した

### 記号のショートカットを、キーの刻印どおりに

記号のキーを位置（英語配列での名前）だけで見ていたので、日本語キーボードでは「[」のキーで
Ctrl+] が、「]」のキーで Ctrl+\ が動いていた。

- 今の配列でそのキーが打つ文字を調べ（`navigator.keyboard.getLayoutMap()`）、記号と比べる
- 日本語配列には Shift を押さずに打てる「=」のキーが無い。Shift+「-」を「=」として受けると
  Ctrl+Shift+-（縮小）と区別できないので、英語配列での位置にある「^」のキーを使い、
  メニューにも「Ctrl+^」と出す
- 配列が分からない間（起動直後・この機能の無い環境）は、従来どおり位置で判定する
- 判定は `src/shortcut-keys.js` に切り出し、`.verify-shortcut-keys.mjs` が英語配列と日本語配列の
  両方で固定している。**実際の日本語キーボードでは確かめていない**（配列の表は手で書いたもの。
  「¥」のキーが返す文字など、実機でしか分からない部分がある）
- **以前の版で、日本語キーボードから記号のキーに独自の割り当てを登録していた場合**、その登録は
  「位置の名前」で保存されているため、押すキーが変わる。登録し直してもらう必要がある
  （リリースの変更点に書くこと）

### 見た目

- 一覧の行は、マウスを乗せた行を、選択中の行の半分の濃さにした（新しい色は足していない）
- 取扱説明書の見出しとカスタムCSS画面の題名を、本体と同じゴシックにそろえた
- 何も書いていないMarkdownの文書に、薄い案内を出す
- 表の操作ボタンの記号を、文字からSVGにした

## 直していないもの（理由つき）

| 項目 | 理由 |
|---|---|
| 保存すると属性・アクセス権・シンボリックリンクが失われる | 一時ファイルに書いて置き換える今の方式は、書きかけで壊れないための安全策。保ったまま直すには実機での検証が要る |
| 「設定をすべて既定に戻す」で、Windowsへの登録（関連付けなど）が残る | 実機でしか確かめられない |
| 開けないファイルを指定して起動すると、空のウィンドウが数秒残る | 実機でしか確かめられない |
| Pandoc でのエクスポートで相対パスの画像が落ちる | Pandoc のある環境でしか確かめられない |
| 脚注の定義がリンクの見た目になる | クリックしたときの動きまで含めて調べてから |
