# 修正: カスタムCSSの作成補助で確かめられない項目

カスタムCSSの作成補助（仕様書 第2.10.1節 C-16、PR #40）を作った直後、利用者から
「コードモードの確認ができない」と指摘された。ほかにも確かめられない項目がないかを
実測で洗い出し、見本と入力欄を直した記録。

## 何が問題だったか

最初の版の見本は Markdown の文書を1つ表示するだけだった。見本に何を並べるかを、
「Markdown の見た目を決める要素」という頭の中の一覧で決めていた。

## 何を調べたか

sample.css と style.css に載っている変数（70個）を1つずつ目立つ値
（`rgb(255, 0, 255)` など）に変え、見本を撮り直して、1画素でも変わるかを比べた。

最初の測定（Markdown の見本だけ、1枚の基準画像と比べる）では、70個のうち32個が
まったく見た目を変えなかった（下の表）。

見本を3つに増やしたあとの測り直しでは、何もしなくても画面がわずかに揺れる分
（描画の後追い）まで「変化あり」に数えてしまい、使われていない変数まで全部が効いているように
見えた。変数ごとに「変える直前の画面」を撮り直し、さらに2回続けて同じ画面になるまで待ってから
比べる形にして、揺れを取り除いた。全体を撮る方式（`fullPage`）は毎回わずかに揺れたため使わず、
縦に長い画面で通常の撮り方にした。最初の測定にもこの揺れが混じっていた可能性があるため、
下の表は「少なくともこれだけは確かめられなかった」という数である。

| 分類 | 変数 | 理由 |
|---|---|---|
| コードモード | `--active-line-bg` `--fold-guide-hover` ほか | 見本にコードモードが無い |
| 画面の周り | `--chrome-bg` `--chrome-fg` `--menu-hover-fg` `--sidebar-bg` `--titlebar-bg` `--titlebar-fg` `--surface` `--input-bg` `--shadow-pop` `--radius` `--accent-hover` | 見本に本文しか無い |
| Markdown の要素の抜け | Callout の TIP・IMPORTANT・CAUTION、`--frontmatter-bg` | 見本の文書に書いていなかった |
| どこにも効かない | `--pre-bg` `--pre-ink` `--status-ok` `--status-off` `--status-pend` `--shadow-card` `--topbar` `--topbar-ink` `--bar-h` | 参照している指定が無い、または指定の相手（`.topbar` `.mobile-bar` `.save-status` 等）が画面に無い |
| 見出しの書体 | `--font-heading` | 取扱説明書の見出しにしか使われていない |

## 入力欄の誤り

最初の版の入力欄には、効かない変数を2つ出していた。

- 「コードブロックの背景」に `--pre-bg`。sample.css に「フェンスコードブロックの背景色」と
  説明されていたのを信じた。実際のコードブロックの背景は `--code-bg`（インラインコードと共通）。
  `src/themes.css` の冒頭には「使われないまま残っている死んだトークン」と既に書かれていた。
- 「見出しの書体」に `--font-heading`。本文の見出しは `--font-body` で描かれる。

どちらも、変数の名前と sample.css の説明から効き目を推測し、実際に変えて確かめなかった。

## どう直したか

- 見本に「Markdown / コード / 画面全体」の切り替えを足した（`src/css-preview.html`・`src/css-preview-entry.js`）
  - コード: JS のコードをコードモードで表示する。行番号・今の行・折りたたみ・インデントの線・
    半透明の色の見本（市松模様 `--cp-checker`）が出る
  - 画面全体: タイトルバー（Windows が描くため同じ色の帯で代わりに見せる）・メニューバー・
    サイドバー・ステータスバー・コマンドパレット・ダイアログ・設定画面のボタンを、
    本物と同じ id とクラスで並べる。ステータスバーの指定は `index.html` にしか無いため写しを置き、
    写しがずれていないかを `.verify-css-editor.mjs` で比べている
  - Markdown: Front Matter と Callout 5種を足した
- 入力欄を見本の画面ごとの組（本文・Callout・コード・画面・書体）に分け、触ると見本がその項目の
  見える画面に切り替わるようにした。`--pre-bg` と `--font-heading` は外した
- どこにも効かない変数と、画面に無い部品の指定を `style.css`・`themes.css`・sample.css から消した
  （利用者の判断）。`--pending` は、揺れを取り除く前の測り方では「変化あり」に数えていたため
  上の表に入っていなかったが、揺れを取り除いて測り直すとどこにも効かず、`.save-status`
  （画面に無い）にしか使われていなかったため一緒に消した
- `.verify-css-preview-coverage.mjs` を足した。sample.css と入力欄に出している変数が、
  どれかの見本で必ず見た目を変えることを確かめる。マウスを乗せたときだけ使われる変数
  （`--fold-guide-hover` `--danger-soft` `--accent-hover`）は、その部品にマウスを乗せてから撮る

## 直さなかったもの

- 右クリックのメニューと、メニューバーから開くメニューは Windows が描いており
  （`Pane/NativeMenu.cs`）、配色はテーマごとに決め打ちしている。カスタムCSSでは変わらない。
  見本には出さず、画面全体の見本の下にそう書いた
- 本文の余白・行の高さ・最大幅（`--editor-padding-*` `--editor-line-height` `--editor-max-width`）は、
  設定画面の値が要素に直接書き込まれてCSSからは効かないため、入力欄には出していない
  （見本では効くので、見本だけ見ると効きそうに見える点は残っている）
- 見本がフォーカスを持たないため、本文の選択範囲の色は見本の本文では見えない。同じ
  `--accent-soft` を使うサイドバーの「今いる所」とパレットの選択行で確かめられる
- `style.css` には、`.layout` `.editor` `.memo-*` `.md-toolbar` など、ほかにも画面に無い部品の
  指定が多く残っている。今回は消した変数に関わるものだけを消した
