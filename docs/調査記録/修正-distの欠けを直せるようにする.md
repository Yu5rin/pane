# dist の欠けに気づき、最新版を取って直せるようにする

## きっかけ（2026-09-24）

ある1台のPCで、Paneの画面が崩れて表示された。

- メニュー（ファイル・編集…）や右上のアイコンが、枠付きの標準のボタンになる
- 右上のアイコンが右に寄らず、「書式」のすぐ後ろに並ぶ
- コピーとチェックマーク、太陽と月が**両方とも**表示される
- サイドバーの検索欄やチェックボックスも標準の見た目になる
- 一方で、サイドバーと本文の横並び、下のステータスバーは崩れていない

## 調べたこと

### 1. 何が効いていないのか

`style.css` を読み込ませずに起動すると、報告の画面とほぼ同じになった
（Playwrightで `style.css` への要求だけを止めて撮影）。

横並びやステータスバーが崩れないのは、それらを `style.css` ではなく
`index.html` の中の `<style>` で決めているため。つまり「CSSが全部効いていない」のではなく
「`style.css` だけが効いていない」形だった。

### 2. なぜ効いていないのか — 候補を2つに絞った

| 候補 | 中身 |
|---|---|
| A | そのPCの `dist\style.css` が無い・壊れている |
| B | ファイルはあるが、WebView2 が「CSSではない」と判断して適用を拒んでいる |

B は、Windowsのレジストリで `.css` の種類（`HKEY_CLASSES_ROOT\.css` の `Content Type`）が
書き換えられているPCで起こりうると考えた。ただし公開情報で見つかったのは、Python や Go の
サーバーがレジストリを読んで `.js` を `text/plain` で返す事例で、**WebView2 が同じ判断をすると
書いた一次資料は見つからなかった**。推測のまま手を打たず、そのPCで事実を取ることにした。

### 3. そのPCでの結果

Pane を起動したまま PowerShell で確かめてもらった。

```
Pane.exe  : C:\追加\Pane\Pane.exe
style.css : 見つかりません
.css種類  : text/css
WebView2  : 153.0.4234.48
```

- `.css` の種類は `text/css` で正常 → **B ではない**
- WebView2 は新しい版で問題なし
- **`dist` はあり（画面が出ている）、その中の `style.css` だけが無い → A**

Pane が読む `dist` は「Pane.exe の隣」で決め打ち（`MainForm.ResolveDistPath`）なので、
確かめた場所も正しい。

### 4. なぜ1つだけ欠けたのか — 突き止められていない

Pane の「更新する」（`UpdateService.ApplyUpdate`）は、`dist` の全ファイルを1つずつコピーし、
どれか1つでも失敗すれば全体を元に戻す作りで、**1ファイルだけ黙って欠ける経路はコード上に無い**。
残る可能性は次の2つ。

1. 手で置いたときに抜けた
2. 置いた後で外から消された（ウイルス対策の隔離、掃除ツールなど）

見分けるためにログ（更新で置いたときの `distを読み通した(208ファイル, …)`）と
ファイル数を確かめてもらう予定だったが、確認の前に直した（Zipの展開し直し）ため、
**原因は分からないまま**になっている。同じPCでまた起きたら、直す前に確かめたい。

## Pane自身が気づけなかった理由

起動時は `dist\index.html` の有無しか確かめていなかった。`style.css` が無くても
`index.html` と `main.js` があれば起動し、ボタンも押せる。見た目の定義が丸ごと無いまま、
**崩れた画面で何も言わずに動き続けていた**。ログにも何も残らず、利用者の手元で
PowerShellを実行してもらうまで原因が分からなかった。

## どう直したか

利用者要望は「欠けていたら、最新版をダウンロードして修正するようにして」。

1. **起動時に確かめる**（`DistIntegrity.FindMissing`）
   プロセスで1回、最初のウィンドウを開くとき。欠けていれば、欠けたファイル名をログへエラーとして残す。
   突き合わせる相手は下の「全ファイルの一覧」を参照。
2. **尋ねる**（`DistRepairFlow`）
   ウィンドウが見えてから「最新版をダウンロードして直しますか?」。**「はい」を押すまで通信しない。**
   Paneは利用者の操作なしに外へ通信しない方針で、この「はい」がその操作になる。
3. **同じ版でも取り直す**（`UpdateService.CheckAsync(forRepair: true)`）
   通常の更新は「配布元の方が新しいとき」だけ進む。欠けたPCはまさに最新版を使っていたので、
   そのままでは「最新版です」で止まる。修復では同じ版でも配布物の場所を返すようにした。
   会社の回線でGitHub APIが上限に当たる件（v1.1.7）への対処（URLを規則から組み立てる）も、
   そのまま効く。
4. **置き直して再起動する**
   ダウンロード・SHA256照合・入れ替え・再起動は、「更新する」と同じ部品を使う。

### 判断したこと

- **確認・進み具合・失敗の知らせは、すべてWindows標準の画面で行う。**
  欠けやすいのはまさに `style.css` で、「更新する」ボタンのある設定画面も同じ `style.css` で
  描いている。欠けた状態では設定画面も崩れるため、そこへ誘導しても直せない。
- **配布元の版の方が古ければ断る**（`UpdateCheckLogic.IsOfferable`）。
  手元で作った開発版などを「直す」つもりで古い版へ戻してしまわないため。
- **入れ替え中の印を「更新する」と共有した**（`UpdateService.TryBeginApply`）。
  以前は設定画面側（`SettingsBridge`）だけがこの印を持っていた。入口が2つになると、
  入口ごとの印では他方が素通りする（「繰り返し出てきた誤り」8の形）。実行する側に1つだけ置いた。
- **自動で直せないとき**（通信できない・書き込めない場所・未保存の変更がある）は、
  理由と手で直す手順を示し、リリースページを開くかを尋ねる。

### テストで固定したこと

- `DistIntegrityTests`: 欠けの判定、文面、**主要10ファイルが `scripts/build.js` の置くものと一致すること**
  （build.jsへファイルを足したのに一覧を直し忘れると落ちる。一覧から1つ外すと2件落ちることを確認済み）
- `UpdateCheckLogicTests`: 取りに行ってよい版の判断（通常の更新と修復の違い）

## 全ファイルの一覧で突き合わせる（利用者要望）

最初は、名前の変わらない主要10ファイル（`index.html` `style.css` など）だけを確かめる形にした。
名前にハッシュが付く分割ファイル（Mermaid等、約200個）は版ごとに名前が変わり、Pane側で
決め打ちできないためである。しかし「それらが欠けても気づかない」ことを伝えたところ、
全ファイルの一覧で突き合わせる形にしてほしい、となった。

名前が版ごとに変わる以上、「何を置いたか」を知っているのはビルドした本人だけなので、
**ビルドが書き出す**形にした。

- `scripts/build.js` が、esbuild の出力が確定した後（`onEnd`）に `dist/dist-files.json` を書く。
  形は `{"format":1,"files":[...]}`。区切りは `/`、名前順、一覧そのものは載せない。
  watch 中も差分ビルドのたびに書き直す（書き直さないと新しい分割ファイルが載らない）。
  失敗したビルドの一覧は書かない（中途半端な `dist` を正しいものとして記録しないため）
- Pane は起動時に、この一覧と主要10ファイルを合わせて確かめる。主要10ファイルを別に
  持ち続けるのは、一覧そのものが欠けたり壊れたりしても、画面を描くのに欠かせないものだけは
  確かめられるようにするため
- 一覧が無い・読めない・知らない版・`dist` の外を指す名前（`..` や絶対パス）を含む場合は、
  **一覧そのものを欠けとして扱う**。一覧が無ければ全部は確かめられないし、直せば一覧も戻る。
  一部だけ読めた一覧の残りを信じる、ということはしない
- 約210個の有無を確かめるので、UIスレッドではなく裏のスレッドで行う（起動時間の目標、仕様書 第8.4節）

### 一覧がずれていないことを固定した

一覧がずれると、正常な配布物でも毎回「欠けている」と言い出すか、欠けても気づかないかの
どちらかになる。どちらも利用者の手元では気づきにくい。

- `.verify-dist-files.mjs`（`npm run verify` の1本）: ビルド直後の一覧と実際の `dist` を突き合わせる。
  `dist` にファイルを1つ足しても、1つ消しても、それぞれ2件落ちることを確認済み
- `DistIntegrityTests`: 一覧の読み方（壊れた一覧・`dist` の外を指す名前の扱い）と、
  一覧のファイル名・形の版が `build.js` と一致すること

## 直さなかったこと

- **`dist` に余分なファイルがあっても何もしない。** 手で上書きしたときに残る古い分割ファイルなど。
  欠けとは違い、画面が崩れる原因にはならない。
- **常駐中に欠けた場合は、次に Pane が起動し直すまで気づかない。**
  確かめるのはプロセスで1回だけ。ウィンドウを開くたびに約210個を確かめるほどの頻度は要らないと判断した。
- **`dist` フォルダごと消した場合の動きは確かめていない。** WebView2 が存在しないフォルダを渡されたときに
  止まるかどうかを、Linux では試せないため。
- **コピーとチェックマークが両方出る件。**
  v1.2.1で、チェックマーク側の `hidden` 属性をやめてCSSだけで隠す形にした
  （`docs/調査記録/修正-コピーの手応え.md`。SVGでは `hidden` をJSから外せないため）。
  そのためCSSが効かないと両方出る。CSSが欠けた状態は今回の変更で検知して直せるようになったので、
  ここは戻さない。
- **欠けた原因**は上記のとおり分からないまま。
