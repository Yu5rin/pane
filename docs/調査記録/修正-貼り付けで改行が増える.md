# 貼り付けると行の間に空行が入る

対応した版: 次の版

利用者からの報告。メールソフトから21行のテキストを貼り付けたら35行になった。
行の間に空行が入り、行頭の全角スペースも消えていた。

## 何が起きていたか

貼り付け(`main.js` の `onPaste`)は、クリップボードに `text/html` があれば必ず
`htmlToMarkdown()` を通していた。

送り元のアプリは、ただの複数行テキストをコピーしたときにも `text/html` を一緒に載せる。
その中身は各行を `<div>` や `<p>` で包んだだけである。`htmlToMarkdown()` は最後に

```js
return out.join("\n\n");
```

としており、ブロックの区切りに空行を入れる。段落どうしならそれが正しいが、
「1行=1ブロック」のHTMLでは行数がほぼ倍になる。

内容18行 + 空行17行 = 35行。報告の数字とちょうど合う。

副作用も2つあった。`inline()` が `textContent.replace(/\s+/g, " ")` で空白をまとめ、
`trim()` するため、

- 行頭の全角スペース（`　　制御ケーブル116芯`）が消える
- 連続した半角スペース（`90m  2本/台`）が1つに縮む

HTMLの空白の扱いとしては正しいが、書式が何も無いHTMLに対してそこまでする理由は無い。

## どう直したか

書式（見出し・リスト・表・引用・コード・リンク・画像・強調・区切り線）が
**1つも無い**HTMLは、変換しても得るものが無い。プレーンテキストをそのまま貼る
（`htmlIsPlainTextLike()`）。

実測（4通りの送り元を想定、元テキスト11行）:

| 送り元の形 | 修正前 | 修正後 |
|---|---|---|
| 各行が `<div>`（Outlook/Gmail風） | 15行 | **11行** |
| 各行が `<p>`（Word風） | 15行 | **11行** |
| `<br>` 区切り | 15行 | **11行** |
| HTMLなし | 11行 | 11行 |

書式のあるHTMLは従来どおり変換される（見出し・リンク・強調・引用・表・コード・
画像・区切り線を回帰テストで固定した）。

### あわせて直した: 箇条書きの項目間にも空行が入っていた

同じ `out.join("\n\n")` が原因。リストの項目を1つずつ `out` へ積んでいたため、

```
- あ

- い
```

となり、Markdownとして「ゆるいリスト」（各項目が段落として描かれる）になっていた。
表と同じく、リストは1つのブロックにまとめてから積むよう直した。

## 直したつもりで、入口を1つ漏らしていた

最初の修正は `onPaste`（Ctrl+V などの本物のpasteイベント）にだけ判定を入れていた。
利用者から「右クリック→貼り付けだと改行が入る」と再指摘されて気づいた。

貼り付けの入口は2つある。

- `onPaste` … 本物のpasteイベント。`e.clipboardData` を読む
- `pasteRichFromContextMenu()` … 右クリック・編集メニューから。`navigator.clipboard.read()` を読む

後者は `htmlToMarkdown()` を無条件に呼んだままだった。

**`調査-ウィンドウ表示の300ms超過.md` で「入口が複数あるものは、入口ごとではなく
実行する側で塞ぐ」と書いた直後に、同じ形の漏れをまた作った。**

判断を `markdownFromClipboardHtml()` 1つに集約し、両方の入口がそれを通るようにした。
回帰テストにも右クリック経路の節(C)を足した。テストが片方の入口しか見ていなかったから、
漏れに気づけなかった。

### 右クリック経路をテストから叩く方法

コマンドは「最後にメニューを開いた側」へ配られる（`commands.js` の `activeNativeOwner`）。
`menu-command` をいきなり送っても何も起きない。先に `contextmenu` を発火させて
メニューを開いた状態を作る必要がある。

項目のidは `ctx0`, `ctx1` … と並び順で振られるため、決め打ちにすると項目が増減した
ときに黙って別の項目を押すことになる。`open-context-menu` で送られる項目一覧から
ラベルで引く。

## 調べている最中に自分が間違えたこと

**`.cm-content` の `innerText` で行数を数えて、22行という誤った数字を出した。**
CodeMirrorの各行はブロック要素なので、`innerText` はCSSに従って余分な改行を入れる。
正しくは15行だった。

本文は `request-text` メッセージで取れば、エディタが持っている文字列そのものが返る。
回帰テスト（`.verify-paste-plain.mjs`）にもその旨を書いてある。

計測の道具が結果を変えていないかを、数字を出す前に確かめること。この調査だけで
2回目である（`調査-ウィンドウ表示の300ms超過.md` も同じ形）。
