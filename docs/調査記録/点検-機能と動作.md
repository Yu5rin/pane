## 指摘

### [高] 復元ダイアログで「はい」を選んだ直後、元のスナップショットを即削除するため、復元ウィンドウが立ち上がる前に落ちると未保存内容が消える
- 該当: `Pane/PaneApplicationContext.cs:178-217` RunRecoveryAndInitialOpen(「はい」でも `AutoSaveService.DeleteSnapshot(windowId)` を無条件に呼ぶ、L214)
  / `Pane/MainForm.cs:1334` "ready" 受信時に `RestoreFromSnapshot` → `SetDirty(true)` するだけで `WriteSnapshot` は呼ばない(次の自動保存Tick=既定30秒後まで書かれない)
- 再現: 異常終了 → 再起動 → 「復元しますか」に「はい」 → 30秒以内にもう一度落ちる(または WebView2 の初期化に失敗して "ready" が来ない、電源断、タスクマネージャで強制終了)
- 何が起きる: 復元元 `{windowId}.json` は既に消えており、新ウィンドウ側のスナップショットはまだ無いので、未保存内容が完全に失われる。WebView2 Runtime の破損など「毎回起動に失敗する」状況では復元の機会が1回しか無く、その1回で消える
- 直し方の方向: 「はい」のときは新ウィンドウの WindowId で先に WriteSnapshot(コピー)してから旧ファイルを消す、あるいは RestoreFromSnapshot 内で即時 WriteSnapshot する

### [中] settings.json がJSONとして壊れていると、既定値で起動した直後の最初の設定書き込みで壊れたファイルごと既定値で上書きされ、全設定が消える
- 該当: `Pane/SettingsService.cs:35-56` Load(JsonException→`new AppSettings()`) / `:94-102` Update(Load→modify→Save) 
- 再現: settings.json を手で編集して構文を壊す(末尾カンマ、数値欄に文字列 "editorFontSize": "abc" 等) → 起動 → テーマ切替・ファイルを開く(RecentFiles更新)など何か1つ設定を触る
- 何が起きる: 起動自体はできる(仕様どおり)が、最初の Update() で既定値ベースの設定が書き戻され、最近使ったファイル・関連付け・テーマ・フォント等の全設定が失われる。壊れたファイルのバックアップ(settings.json.bak 等)も取らず、ログにも「設定ファイルが壊れていた」旨が残らない(catchが無言)
- 型不一致でも同じ: System.Text.Json は 1項目でも型が合わないと全体を JsonException にするため、1項目の手違いで全設定が飛ぶ

## 問題なしと確認した項目(既存の防御・テストで固定されているもの)
- 設定キーの配線: JS 106キー ↔ C# 取得側/保存側とも一致(上記)。数値欄の空欄/NaN は JS(settings.js:1184, coerceOutgoing)と C#(AppSettings の setter でクランプ)の二重で既定値へ倒す
- 設定の同時保存: すべて SettingsService.Update(ロック+再読込+一時ファイル→Move) 経由。直接 Save() を呼ぶ箇所なし
- 設定ファイル破損時の起動: Load が JsonException を握って既定値で起動する(ただし上記[中]の「上書きで消える」問題あり)
- アトミック保存: 一時ファイル → File.Move(overwrite) の順で正しい。失敗時は一時ファイルを消して原本を残す。保存後にサイズ検証(VerifySavedSize)。fsync 相当(FileStream.Flush(true))は無いが、Windows の MoveFileEx 置換で実用上は足りる
- 更新の確認: 全体20秒/Atom 8秒/API 15秒のタイムアウト、403 は専用メッセージ、その他は `更新を確認できませんでした(型名)`、Atom 失敗は API へフォールバック(UpdateCheckLogicTests で版比較・Atom 解析を固定済み)
- Zip ダウンロード: 上限バイト数(サイズ+1MB or 500MB)、SHA256 照合失敗で削除して中止、HTTPS 以外拒否、失敗時は一時フォルダごと削除
- 更新の入れ替え: 例外時のロールバックあり。新版は `--after-update <pid>` で旧プロセス終了を待つ(15秒上限)。退避ファイルの掃除はバックグラウンド
- 多重起動: Mutex + 名前付きパイプ、パイプ応答なし(2秒)は自プロセスで続行。UI ブロック中でも 1.2 秒で ACK を返す
- 空欄・不正入力: グローバル検索の空文字/不正正規表現は null で中断(SearchService.BuildRegex、Regex に 1秒の MatchTimeout)、行ジャンプは 1〜最終行にクランプ(editor.js:5049)、エディタ内検索は @codemirror/search に委譲
- フォルダ走査: 10,000 件で打ち切り、サイドバーに注意書き(sidebar.js:414)。CancellationToken でウィンドウ破棄時に停止
- ログ: キュー上限 50,000 行で以降は捨てる(Logger.cs:MaxPending)。古いログ削除は pane-*.log のみ
- 画像挿入のファイル名: GetFileNameWithoutExtension で区切り文字を落とすため `..\` 指定で文書フォルダ外へは書けない。空名は image に置換
- PATH への追加: DoNotExpandEnvironmentNames で読み、既存の値種別(REG_SZ/REG_EXPAND_SZ)を保つ
- ドロップで開いた内容(パス無し)は _currentPath=null で保存時に「名前を付けて保存」になる。パイプで渡されたフォルダは Directory.Exists で振り分け
- 自動保存: request-text 送信時のパスと応答時のパスを突き合わせ、途中で別ファイルを開いていたら破棄(MainForm.WriteAutoSaveSnapshot)。JS 側は text-response / all-tabs-text-response とも必ず text を載せる
- Windows 予約名(CON/NUL 等)は SaveFileDialog が弾く。ファイル名に改行は Windows で不可なのでパイプの1行プロトコルは安全
