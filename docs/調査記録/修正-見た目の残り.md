### 2. 指摘15(タブバーの横スクロールバー) — 完了

事実確認: `src/style.css`のコメント通り、以前「専用の指定は不要」として意図的に
`scrollbar-width:thin`の個別指定を外した経緯があった。#tabbarは高さ32px固定で
`.tabbar-list`はalign-items:stretchでその高さいっぱいに広がるため、共通の17px
横スクロールバーが出ると理屈の上では32-17=15pxまで潰れる。
**ただしこの開発コンテナ(Linux headless Chromium)はオーバーレイスクロールバー
(レイアウトへ場所を専有しない)になっており、実際に高さが潰れる様子を
Playwrightで再現できなかった**(`<div style="overflow:scroll">`の素の実験でも
clientWidth==offsetWidthでスクロールバー分の差が全く出ないことを確認)。Windows/
WebView2はclassic scrollbar(レイアウトを専有する)が既定のため、実機では
指摘どおり起きると判断し、コード上の理屈(align-items:stretch+固定height32px+
横スクロールバー)に基づいて修正した。

修正: `.tabbar-list::-webkit-scrollbar { height: 4px; }` を追加(他の色・ホバー時の
見た目は共通の`*::-webkit-scrollbar-thumb`等をそのまま使うため、太さ以外は統一
されたまま)。以前の「他と揃える」判断自体は妥当だが、32pxという特に狭い高さの
場所だけは17pxと両立できないため、コメントに再検討の経緯を残した。

検証: `.verify-tabs.mjs`に(J)節を追加。レイアウト高さでは再現できないため、
スタイルシート上の`.tabbar-list::-webkit-scrollbar`ルールの値そのもの
(document.styleSheetsを走査)を確認する形にした。**修正前のCSSに対して実行し、
ルールが存在せずNGになることを確認済み**(git show HEADの内容を一時ディレクトリへ
展開し、PORTだけ差し替えて実行)。修正後は`.verify-tabs.mjs`単体で
**OK 60 / NG 0**(J節2件を含む)。

事実確認: 事実どおり。実測(幅960pxでサイドバーを上限480pxまで広げてCtrl+H)で

極端なケースは仕様書に定めのある最小ウィンドウ幅が無い中でボタン類を
犠牲にしてまで潰すのは影響が大きいと判断し、意図的に許容している(指摘11で
MainFormにMinimumSizeを付けることで、実機ではこの極端な幅自体に到達しにくく
